## 1. 한 문장으로
**꼬인 선 하나가 풀려 나와 아홉 개의 점을 지나 `&`에 닿는다.** 화면은 고정된 창이고, 그 창이 선을 따라 미끄러진다. `&`는 늘 창의 한가운데 있고 세계가 그 아래로 흐른다.

## 2. 세계(world) 좌표계
- 세계는 **1440×900 화면을 기준으로 그린 고정 캔버스**(단위 = px). 다른 화면 크기에서는 `scale = min(vw/1440, vh/900)`로 통째로 축소·확대한다. 구도가 화면마다 달라지지 않고, 판·글자·선이 함께 커진다(포스터를 확대하는 것과 같음).
- 세계 크기: 약 **3600 × 5400** (가로 2.5화면 × 세로 6화면). 그림 2의 비율(위에 꼬임, 아래로 굽이침)을 따른다.
- 카메라: `world.style.transform = translate(vw/2 - P(t).x·s, vh/2 - P(t).y·s) scale(s)`. 회전 없음(글자는 항상 수평).

## 3. 경로(path)

### 3.1 형태
1. **꼬임(0장면)**: 세계 상단 중앙, 약 700×420 상자 안의 스크리블(고리 6~8개, 3~4번 교차). 선의 시작은 상자 왼쪽 위 밖에서 들어온다(그림 1의 왼쪽 위 점).
2. **풀림**: 꼬임 오른쪽 아래로 한 가닥이 빠져나와 첫 큰 굽이로.
3. **굽이 6개**: 좌↔우로 크게 왕복하며 내려간다. 진폭 1200~1800px, 한 왕복 높이 900~1100px. S자마다 곡률이 다르게(단조로움 방지).
4. **끝**: 마지막 굽이가 짧아지며 수평에 가깝게 들어와 `— & —` 자리(세계 하단 중앙)에서 멈춘다. 오른쪽 가로선 없음(현행과 같음).

### 3.2 수학
- 하나의 SVG `<path>`, 3차 베지어 연속(C1: 이음점에서 접선 방향·크기 일치).
- 길이 매개변수 `t ∈ [0, L]` (`getTotalLength`), 위치 `P(t) = getPointAtLength(t)`. 접선은 `P(t+1) − P(t)`.
- **점(장면) = 특정 t**: `T = [t0 … t8]`. 스냅·진행 지도·해시는 전부 이 배열.

## 4. 장면(판)
- 판 = **상자가 아니라 글자 자리**(2026-09-20 결정: 배경·테두리 없음, 문의 판의 navy 면도 없음 → 14 §3.3의 "지면"과 S4 색 반전은 이 시안에서 쓰지 않음). 헤드라인·보조문·도형(navy-100)이 세계 위에 직접 놓이며 0·8 장면과 같은 문법. 640×420은 배치·겹침 계산용 영역이고 화면에는 보이지 않는다. 크기 **640×420 화면 px 고정**(2026-09-20). 판·헤드라인·끝 장면의 글자는 세계 스케일에서 제외되어 어떤 창에서도 같은 크기다(§12-1). 세계 안에서 판이 차지하는 넓이는 `640/s × 420/s`.
- **판의 위치**: 점에서 접선의 바깥쪽(곡선의 볼록한 쪽)으로 56px 떨어져 붙는다. 그 뒤 **실제 창 기준으로 clamp**(가장자리 24px·헤더 84px 화면 px, 장면의 어느 점에 서 있어도 판이 다 보이게)하고, 선이 판을 지나면 창 안에 남는 자리로만 접선 방향으로 밀어 피한다. 창이 작아 두 조건을 다 못 채우면 창 안을 우선하고 선은 판 뒤로 지나간다. 점 자체는 선 위에 남고 `&`가 도착하면 그 위에 선다(현행과 같음).
- 표시(2026-09-20 개정): **지금 장면(경로 거리로 가장 가까운 장면)의 판만 보인다.** 두 장면의 중간 지점에서 지금 판이 8px 내려가며 페이드 아웃(350ms), 다음 판이 8px 떠오르며 페이드 인. 되돌아오면 반대. 무엇을은 첫 점~셋째 점 구간이 한 장면(칩도 같은 규칙). 인트로의 "첫 점 판 미리 보기"는 제거(t=0에는 헤드라인만). ~~지나간 뒤에도 남아 있다~~ 는 폐기.
- 판 내용: 지금 v5의 9장 그대로(21 문구). 문의 판도 밝은 바탕, navy는 1차 버튼에만.
- 판이 없는 점(0, 8): 헤드라인·캡션이 세계에 직접 놓인다(포스터 위의 글자).

## 5. 카메라와 입력
| 항목 | 규칙 |
|---|---|
| 상태 | `t`(목표) / `tPos`(현재), smoothDamp 0.26s — 현행 엔진 그대로 |
| 휠 노치 / 방향키 | 다음·이전 점의 `ti`로 목표 갱신(현행 규칙: 스트림 하나 = 점 하나, 큐) |
| 속도 상한 | 세계 기준 **2400px/s**. 넘으면 smoothTime을 늘려 감속 |
| 곡률 감속 | 접선 방향 변화율이 큰 구간(굽이 정점)에서 목표 속도 ×0.7 — 카메라가 코너에서 자연스럽게 느려짐 |
| 앞보기(lookahead) | 카메라 중심을 `P(t)`가 아니라 `P(t + 120·v/vmax)`로 — 빠를수록 앞을 본다. 정지 시 0 |
| 무엇을 고정 카메라 | 세 점(고치기·옮기기·만들기)을 지나는 동안 카메라는 **가운데 점에 고정**, 잉크·점·칩만 `t`를 따라 진행. 앞뒤 300px 구간에서 경로 위 카메라와 smoothstep으로 이어붙임(`camT(t)`, 2026-09-20) |
| `&` 마커 | 화면 중앙 고정(선 위 20px). 세계가 움직인다. 점에 서면 점 위 |
| 잉크 | 선은 `t`까지 그려짐(현행). 앞은 옅은 안내선 |
| 진행 지도 | 점 9개(무엇을은 1칸에 점 3개). 현재 = `&`가 있는 점 |
| 해시 | `#p0n` 동기화, 직접 진입 시 인트로 생략 |
| 이동 중 축소 | 유지 가능(세계 scale에 곱함). 토글로 |

## 6. 인트로 (0 → 1)
1. 로드: 꼬임이 1.4초 동안 그려진다(stroke-dashoffset). 헤드라인은 즉시.
2. `&`가 꼬임 끝(풀리는 지점)에 놓인다(페이드 0.4초).
3. 첫 입력에서 카메라가 풀린 가닥을 따라 점 1로 미끄러진다. 이때만 카메라 속도를 0.8배로 — "풀리는" 느낌.
4. 뒤로 돌아오면 꼬임이 그대로 있다(다시 그리지 않음).

## 7. 끝 (7 → 8)
- 점 8에 도착하면 `&`가 자리(seat)에 앉고, 위 `Prologue`, 아래 캡션·링크가 나타난다(현행). 선은 자리 34px 앞에서 끝난다.
- 더 굴려도 움직이지 않음(끝). 진행 지도 마지막 칸.

## 8. 모바일(≤1023px)·reduced-motion
- 모바일: 경로 없음. 9장면 세로 스택(현행 그대로).
- reduced-motion: 카메라 이동은 즉시 점프(smoothTime 0), 등장·잉크 없음.

## 12. 자체 검토 — 빠진 것과 위험

### 심각 (이대로 만들면 잘못 만들어지는 것)
1. **세계 통째 스케일과 글자 크기의 충돌**: `scale = min(vw/1440, vh/900)`이면 1280×720 창에서 0.8배 → 헤드라인 7.8rem(125px)이 100px, 본문 1.2rem(19px)이 15px. 2560×1440에서는 1.6배 → 본문 30px. 14의 타이포 규칙(크기 3단계 고정)과 어긋난다. → **판 안의 글자는 세계 스케일에서 제외**하고(판을 `scale(1/s)`로 되돌린 뒤 판 크기는 CSS px 고정), 경로·점·판의 **위치**만 스케일한다. 판이 화면 대비 같은 비율을 차지하려면 판 크기를 `clamp`로 따로 정한다. **→ 2026-09-20 해결**: `.world{--inv:1/s}`, 모든 `.scene{transform:scale(var(--inv))}`(판·헤드라인·끝 장면 전부). 1280~2560 여섯 창에서 헤드라인 73.6px 고정 확인. 판 크기의 `clamp`는 아직 없음(640×420 고정) — 1280×720에서 판이 화면의 50%×58%를 차지하는 것은 남은 판단.
2. **판이 선을 가린다 ↔ 선이 판 뒤를 지난다**의 z 순서와 잉크 표시: 잉크(그려진 선)가 판 뒤로 들어가면 `&`가 판 위에 있을 때 선의 끝이 안 보인다. → 판은 점에서 **접선 바깥쪽**에 두어(§4) 선이 판을 관통하지 않게 하고, 관통이 불가피한 구간은 경로를 고친다. 검증 (b)를 자동 계산으로.
3. **`getPointAtLength`를 매 프레임 여러 번** 호출(카메라·앞보기·곡률·잉크) — 긴 경로에서 프레임당 4~6회는 괜찮지만, 곡률 계산을 매 프레임 하면 비용이 큼. → 로드 시 `t`를 4px 간격으로 샘플링해 위치·접선·곡률 표를 만들어 두고 보간한다.

### 보강 (만들면서 채울 것)
- 문의 판(navy-950)이 세계 위에 놓이면 판 바깥의 선·점은 밝은 배경 위라 색 전환 문제가 사라진다. 대신 어두운 판 **안**을 지나는 선이 있으면 흰색이어야 함 → 판 안에서는 선을 그리지 않는 규칙으로(판이 점 옆에 있으니 자연스럽게 해결).
- "무엇을"의 점 3개: 한 판에 점 3개면 판이 세 점을 모두 덮을 수 있음 → 판을 굽이 위쪽에 두고 점 3개는 판 아래 선 위에. 카메라가 세 점을 지나는 동안 판이 시야에 머무름(카메라가 300px씩만 움직임). **→ 2026-09-20 확정: 점 3개 세로, 판은 첫 점 오른쪽 가운데, 칩은 점 옆.** 판은 첫 점에서만 온전히 보이면 되고 둘째·셋째 점은 칩(켜짐)이 내용을 맡으므로 "세 점 모두에서 판이 보여야" 하는 제약이 사라짐.
- 뒤로 돌아갈 때 카메라 방향 전환: smoothDamp는 방향 반전에서 속도가 0을 지나므로 자연스럽지만, 앞보기(lookahead)가 부호를 바꾸며 튈 수 있음 → lookahead는 `v`의 부호를 따르되 0 근처에서 0으로 부드럽게.
- 진행 지도의 "칸 폭 ∝ 패널 폭" 규칙은 의미를 잃음 → 점 사이 경로 길이에 비례.
- 해시 진입·새로고침 시 `t`가 점이 아닌 값이면 가장 가까운 점으로.
- 판 등장 상태의 초기값: 첫 화면(점 0·1)은 로드 시 이미 보여야 함("Show the page at rest").

### 확인 필요 (사람에게 물어야 답이 나오는 것)
1. **판의 존재**: 피드백 그림 3은 흰 사각 "판"이 점에 붙어 있다. 우리도 판을 유지할지, 아니면 판 없이 글자·도형이 세계에 직접 놓이는지(더 유려하지만 14의 "지면" 규칙과 어긋남). → 초안은 판 유지, 다만 크기 축소(760×460).
2. **회전**: 카메라가 접선 방향으로 살짝 기울면 더 영화적이지만 글자가 기운다. 초안은 회전 없음.
3. **이동 중 축소** 유지 여부.
4. **세로 스크롤바 노출**: 경로가 아래로 흐르므로 방문자가 세로 스크롤을 기대할 수 있다. 휠은 경로 이동으로 쓰고, 스크롤바는 없음(현행). 그래도 될지.

### 덜어낼 것
- 회전 카메라, 3D(원근) 효과, 판마다 다른 크기 — 이번 범위 밖.
- 곡률 감속·앞보기는 2차(경로 시안 확인 → 엔진 1차 → 리듬 조정).
