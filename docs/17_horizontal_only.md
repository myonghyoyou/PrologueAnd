## 1. 무엇인가

**데스크톱에서 세로 스크롤이 없다.** 페이지는 가로로 이어진 패널 한 줄이고, 휠·트랙패드·키보드·드래그가 모두 가로 이동이 된다. Rauno 원형(`09` §2, `11` §1)을 구조 차원에서 그대로 따르되, 시각 언어는 13·14, 서사는 브랜드명 And/End(S1~S4)로 채운다.

V3(세로)·A(하이브리드)와 무엇이 다른가:

| | V3 세로 한 장 | A 하이브리드 | **가로 전용** |
|---|---|---|---|
| 스크롤 축 | 세로 | 세로 + 섹션 01만 가로(pin) | **가로만** (데스크톱) |
| Rauno 충실도 | 낮음(인터랙션 종류만 계승) | 중간(한 구간) | **높음(구조 전체)** |
| "몇 장 넘겨야 내 문제가 나오는가" | 해결(스크롤 1~2회) | 해결 | **미해결** → 진행 지도(§3.6)와 헤더 점프로 완화 |
| S1 한 선 | 세로로 내려감 | 3구간 | **가로 한 줄 — 가장 자연스럽다.** 선이 곧 스트립의 축 |
| S2 로고가 페이지를 감쌈 | 헤더 `Prologue` / 푸터 `— & —` | 같음 | **첫 패널 `Prologue` / 마지막 패널 `— & —`** — 로고의 윗줄·아랫줄이 페이지의 양 끝 |
| 새 기술 | 없음 | ScrollTrigger pin(첫 도입) | 없음 — Lenis 가로 모드(네이티브 스크롤) |
| 모바일 | 세로 | 세로 | **세로 스택으로 전환**(§3.8). "세로 없음"은 데스크톱에서만 성립 |
| 읽기(Case Study) | 페이지 | 페이지 | **가운데 시트**(내부 스크롤) — §3.7 |

## 3. 동작

### 3.1 스크롤 — Lenis 가로 모드 (V2 자체 엔진 대신)
- 스트립 래퍼 `overflow-x:auto; overflow-y:hidden; height:100vh`, `body{overflow:hidden}`
- `new Lenis({ wrapper, content, orientation:'horizontal', gestureOrientation:'both', lerp:0.1 })` — 세로 휠·트랙패드 제스처가 가로 이동으로 바뀐다(`gestureOrientation:'both'`)
- **네이티브 스크롤이라** 해시 링크(`#p06`), 키보드(←/→/Home/End, Tab 포커스 이동 시 자동 스크롤), 페이지 내 찾기, 스크린리더 순서가 그대로 동작한다. V2의 transform 엔진(`main.cur/target`)은 이것들을 전부 직접 만들어야 했다
- 휠 한 칸: Lenis `wheelMultiplier` 로 100/140px 조정 (§6-① 확인 후)
- `prefers-reduced-motion`: Lenis 끔, 네이티브 가로 스크롤만(휠 세로→가로 변환도 끔 → Shift+휠·트랙패드·키보드·스크롤바)

### 3.2 S1 한 선 — 한 구간
- 트랙 폭 전체(`content.scrollWidth`)의 SVG 하나. 경로: 00 노드 → 가로(y = 58vh 고정) → 09 `&` 자리. 굽힘 없음
- 그려진 길이 = `scrollLeft + 50vw`(선 끝 = 화면 x 50vw), 마지막 뷰포트에서 `&` 자리까지 달려감(v3의 k 규칙 그대로, 축만 바꿈)
- `&` 마커: fixed, x = 50vw, y = 58vh. 08 구간에서 흰색(`#marker.dark`), 09에서 착석(`.rest`)
- 08의 선은 트랙 SVG 위에 08 폭만큼 클리핑된 흰 선 복제(v3 `#line-dark` 방식, 축만 가로)
- 패널 안 미니 다이어그램·06의 노드는 선 끝이 지나는 순간부터 그려짐(같은 진행 변수)

### 3.3 헤더
- `Prologue` 워드마크(로드 후 `&` 분리) · Projects(시트) · 문의(서랍). 08 구간에서 `on-dark`
- 헤더 오른쪽에 **진행 지도**(§3.6) — V2 필름 스트립의 자리

### 3.4 문의 서랍
- V3 그대로(오른쪽 슬라이드, 2단계, `Prologue & 당신의 업무` → 첨부 시 `Prologue & {프로젝트명}`). 열리면 Lenis stop

### 3.5 Projects (시트)
- 07 패널·헤더에서 열림. **가운데 시트**(폭 56rem, 내부 세로 스크롤): 필터 탭 + 행 목록(V3 `projects.html` 내용 그대로). URL `/projects`(history push), 닫으면 스트립 위치 복원
- "스트립은 고정, 목록은 자란다"의 "목록"이 이것

### 3.6 진행 지도 (V2 필름 스트립의 후계)
- 헤더 중앙: 패널 수만큼의 칸. 00·06·08·09는 **긴 칸**, 02~05는 짧은 칸 4개 묶음, 01·07은 가는 칸 — 칸의 폭이 패널 폭에 비례해 "어디쯤"이 보인다. 현재 칸 navy-800, 지나온 칸 navy-400
- 칸 호버 시 라벨(Prologue / 문제 01~04 / 다섯 단계 / Projects / 문의 / &), 클릭 시 이동
- "내 문제가 몇 장 뒤인가"에 대한 답: 헤더 지도에서 문제 4칸이 항상 보인다 + 00 패널의 "작업 보기 →"가 02로 점프

### 3.7 Case Study — 가운데 시트 (읽기는 세로)
- 02~05 패널·Projects 시트에서 열림. **화면 가운데 시트**(폭 56rem, 상하 4vh 여백, 0.985→1 확대 + 페이드 350ms, 배경 어둡게) — V2 `11` §3의 결정을 그대로 가져온다
- 시트 안은 V3 `case.html` 본문(상단 고정 바·메타 표·10단계 번호 레일·03→05 변형·Before & After·Impact·`& 다음 이야기`). **내부 세로 스크롤**
- URL `/projects/[slug]`(history push, 새로고침 시 스트립 위에 시트가 열린 상태로 렌더). 공유·검색은 이 URL이 맡는다
- 대안 "10단계를 가로 챕터 패널로": V2에서 "상세까지 포스터면 피로하다"(`11` §3)로 기각된 형식이라 기본안에서 제외. §6-②에서 다시 묻는다

### 3.8 모바일 (≤1023px)
- **세로 스택**. 패널 00 → 09를 위에서 아래로, 100vw 폭, 높이 자동. 선·마커 없음. 헤더에 `03 / 10`
- Projects·Case Study 시트는 전체 화면
- 즉, "세로 스크롤 없음"은 데스크톱(≥1024)의 성질이다. V2 모바일의 `scroll-snap`은 쓰지 않는다(패널 높이가 제각각이라 스냅이 어색)

### 3.9 이동 중 축소 (2026-09-16 사용자 결정으로 추가 — V2 계승)
- Lenis 속도 `|velocity|`에 비례해 트랙 전체를 **최대 12% 축소**(`scale(1 − min(1, v/36) × 0.12)`), 매 프레임 `ease 0.12`로 따라감. 멈추면 1로 복귀
- **축소 기준점은 매 프레임 화면 중심**(`scrollLeft + 50vw, 50vh`) — V2 `11` §6의 교훈 그대로. 마커도 같은 중심 기준으로 위치·크기를 보정하므로 선 끝에서 떨어지지 않는다
- 헤더·진행 지도·시트는 축소하지 않는다. 축소되면 래퍼의 bone-100이 상하에 드러난다(V2의 회색 바탕 역할)
- reduced-motion: 없음. 시안 조정 파라미터 `?zoom=0.10&vel=30`, `?zoom=0` 끔
- 인터랙션 종류: 이 축소는 "Lenis + scrub"의 스크롤 반응이므로 종류 수는 5종 유지로 본다(`09` §8). 다만 14 §4 "호버 확대 없음"과는 무관(호버 아님)

### 3.10 인터랙션 예산 (`09` §8 — 5종)
로드 선 그리기 / Lenis(가로) + scrub(선·미니 다이어그램·노드·이동 축소) / 호버 / 열기·닫기(서랍·시트) / 제출. **5종 그대로.** 커서 없음
