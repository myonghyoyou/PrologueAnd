## 1. 결정

**컨셉: 구조적 편집물.** 잘 편집된 제안서·연차보고서처럼 읽히는 사이트. 큰 타이포와 넓은 여백(편집물)에 **눈에 보이는 구조**(가는 괘선, 번호, 정렬 축, 단선 다이어그램)를 더한다. 표면은 평평하고, 모서리는 거의 각지며, 장식은 없다. 유일한 "그림"은 업무 흐름을 그린 **단선(monoline) 다이어그램**이다.

한 줄로: **"복잡한 업무를 단순하게 정리한 문서처럼, 사이트도 정리되어 있다."** 브랜드 문장을 형식이 증명한다.

### 왜 글래스모피즘·네오 브루탈리즘이 아닌가
| 후보 | 판단 |
|---|---|
| 글래스모피즘 / 리퀴드 글래스 | 반투명·블러는 "정리"의 반대 인상(겹치고 비침). backdrop-filter로 저사양 기기 FPS 15~30% 하락(`12` §4.1). 주 고객의 사무용 PC·구형 폰에 불리 |
| 네오 브루탈리즘 | 굵은 테두리·오프셋 그림자·원색은 "도발"의 언어. 병원·제조·건설 담당자에게 신뢰를 주는 방향과 반대. 로고의 Didone 세리프와도 충돌 |
| 벤토 그리드 | 포화(`09`·`12`). 정보를 칸에 나누는 것은 "정리"처럼 보이지만 실제로는 카드 더미 |
| 다크 프리미엄 | 가독성·인쇄·공유에 불리, SaaS 포화 |
| **구조적 편집물** | 브랜드 문장·로고·주 고객·2026 트렌드(편집물·따뜻한 미니멀 정착, 안티그리드 상승)에 모두 맞음. 구현 비용 낮고 오래감 |

### 무엇을 Rauno에서 남기고 무엇을 버리는가
- 남김: 한 화면에 말 하나, 종류가 적은 인터랙션, 가벼움, 진행 표시, 큰 타이포
- 버림: 가로 넘김, 놀이 같은 도형, 커스텀 커서. (B2B 방문자에게는 세로 스크롤·기본 커서가 "정리된" 경험)

### 브랜드명이 형식에 남기는 것 — Prologue& = And / End
`Prologue&`은 "Prologue And"이자 "Prologue End"다(`01` §1). **처음과 끝을 함께한다**는 뜻이므로, 사이트도 **처음과 끝이 한 쌍**으로 읽히게 만든다.

| 이름의 뜻 | 형식으로 옮긴 것 |
|---|---|
| **처음(Prologue)** — 만들기 전에 문제를 먼저 정리 | 모든 화면이 "내 작업"이 아니라 "방문자의 문제"로 시작한다. Hero 리드: "만들기 전에, 무엇이 불편한지부터 정리합니다" |
| **끝(End)** — 출시 후 쓰이고 개선되는 데까지 | 5단계의 마지막 Improve에 "출시 후에도" 칩을 둔다. Case Study는 08 Impact·09 Learned로 끝을 보여준다 |
| **처음과 끝이 한 쌍** | Home의 첫 화면(Hero, bone)과 마지막 화면(문의, navy 반전)이 같은 Display 문장 형식으로 서로 호응한다. 헤더는 로고의 윗줄 `Prologue`, 푸터는 로고의 아랫줄 `— & —`(두 가로선 + 앰퍼샌드). 페이지가 로고를 처음과 끝으로 나눠 가진다 |
| **& = 연결** | `&` 글리프(로고의 Didone)는 두 것을 잇는 자리에만 쓴다: 문제 & 사례, Before & After, 문의 서랍의 "Prologue & {프로젝트명}". 아이콘 대신 이것 하나 |
| **끝이 곧 다음 시작(End → And)** | 문의 섹션 카피: "이 페이지의 끝이 프로젝트의 시작입니다." 접수됨 화면: "여기서부터 함께합니다" |
| **`&` 안의 면분할 → 플래그** | 다이어그램의 3단계 "엉킨 선 → 정리된 구조 → 플래그(끝)". 로드 시 선이 처음부터 끝까지 한 번에 그려진다 |
| **로고의 두 가로선** | 섹션 시작 괘선(3.3)이 이 선을 계승한다. 굵기 1px, 번호와 같은 줄 |

발음 이중성(and / end)은 설명하지 않으면 전해지지 않으므로, 푸터에 캡션 한 줄만 둔다: **"Prologue& — and, 그리고 end. 처음과 끝을 함께합니다."** 그 외에는 형식으로만 말한다.

## 2. 원칙 5개

1. **여백이 구조다.** 요소 사이를 선으로 나누기 전에 간격으로 나눈다. 선은 간격이 부족할 때만
2. **위계는 크기 3단계로.** 헤드라인 / 본문 / 캡션. 굵기(600·400)와 색(bone-900·700·500)으로만 구분. 크기 단계를 늘리지 않는다
3. **네이비는 획이다.** 면으로 쓰는 곳은 문의 섹션·푸터뿐. 나머지는 선·글자·버튼
4. **그림은 다이어그램 하나.** 아이콘·일러스트·사진 없음. 스크린샷은 1px 테두리 안의 "증거"
5. **움직임은 답이다.** 사용자의 행동(열기·펼치기·제출)에 대한 응답으로만. 등장 애니메이션은 로드 시 1회

## 3. 구성 요소 규칙

### 3.1 타이포그래피 (Pretendard)
| 역할 | 크기 (데스크톱 / 모바일) | 굵기 | 자간 | 행간 |
|---|---|---|---|---|
| Display (히어로 문장) | 64 / 40px | 600 | -0.03em | 1.1 |
| H1 (페이지·섹션 제목) | 40 / 30px | 600 | -0.025em | 1.15 |
| H2 (항목 제목) | 24 / 21px | 600 | -0.02em | 1.25 |
| Body L (리드) | 19 / 17px | 400 | 0 | 1.6 |
| Body (본문) | 16 / 16px | 400 | 0 | 1.7 |
| Caption (캡션·메타·라벨) | 13 / 13px | 500 | 0.01em | 1.5 |
| Numeral (번호·단계) | 13px | 500 | 0.04em | 1 |

- 줄 길이: 본문 최대 34rem(약 68자). 리드 30rem
- 강조 구절: 색만 바꾼다(navy-800). 굵기·기울임 강조 금지
- 모든 대문자 라벨·eyebrow 금지. 라벨은 문장형 캡션

### 3.2 간격·그리드
- 8px 단위. 섹션 간 128px(데스크톱) / 80px(모바일)
- 컨테이너 최대 1200px, 좌우 여백 최소 24px
- 12컬럼, 거터 24px. 본문 열은 8컬럼(좌측 정렬), 보조 열 4컬럼
- 정렬 축은 **왼쪽**. 중앙 정렬은 문의 섹션의 한 문장에만

### 3.3 면·선·모서리·그림자
| 요소 | 규칙 |
|---|---|
| 모서리 | 2px. 원형은 진행 표시 점과 아바타뿐 |
| 테두리 | 1px. 약 bone-200(구분), 중 bone-300(입력창), 강 bone-900(이미지 매트·2차 버튼) |
| 괘선 | 섹션 시작에 bone-200 1px 가로선 + 왼쪽에 번호(Numeral). 표의 행 구분도 같은 선 |
| 그림자 | 서랍·모달 부상 1종: `0 24px 48px -24px rgba(28,27,24,.35)`. 카드 그림자 없음 |
| 배경 교차 | 섹션은 bone-50, 두 번째 층위(목록·표)만 bone-100. 카드 컨테이너 대신 배경 층위로 묶는다 |

### 3.4 다이어그램 (서명 요소)
- 단선. 기존 흐름 navy-400 1px, 재설계 navy-800 1.5px, 노드 4px 원(bone-50 채움 + navy 테두리), 도착점 navy-800 삼각형(로고 `&`의 플래그)
- 라벨 Caption. 배경 bone-0, 테두리 bone-200 안에
- Before/After는 같은 좌표계에 위·아래로. 스크롤에 따라 Before가 After로 변형(Case Study에서만)

### 3.5 이미지
- **홈 프로젝트 패널에는 화면 캡처를 넣지 않는다(2026-09-16 결정).** 자리는 도형(navy-100) + 선 위의 before→after 미니 다이어그램 + 결과 숫자 1~2개가 채운다(`design/mockups/v3/panels.js`). 캡처는 Case Study·Projects 목록에만, 그것도 공개 범위 확인 후. 확인 전에는 회색 매트에 "공개 범위 확인 후"
- 스크린샷: bone-0 매트 6px + bone-900 1px 테두리. 기울임·원근·기기 목업 없음
- 비율 16:10 고정. 공개 불가 화면은 같은 규격의 Mockup으로
- alt 텍스트에 Before/After의 차이를 적는다

### 3.6 인터랙션·모션 (`09` §8의 5종 안에서)
| 순간 | 동작 | 시간·이징 |
|---|---|---|
| 페이지 로드 | 히어로 다이어그램의 선이 그려짐(stroke-dashoffset), 글자는 즉시 | 1.2s, power2.inOut |
| 스크롤 | Lenis(lerp 0.1). 왼쪽 진행 레일이 현재 섹션 표시 | — |
| Case Study 다이어그램 | Before → After 변형 scrub | 스크롤 비례 |
| 호버 | 링크 밑줄 signal, 버튼 navy-700, 목록 행 bone-100 배경 | 150ms |
| 열기·닫기 | 서랍 슬라이드 + 배경 어둡게, 아코디언 펼침 | 350ms, cubic-bezier(.2,.8,.2,1) |

| reduced-motion | 선 그리기·Lenis·scrub 끔, 최종 상태 즉시 | — |

### 3.7 서명 장치 4개 (2026-09-16 채택 — 브랜드명 "처음과 끝을 함께"의 형식화)
| # | 장치 | 내용 | 인터랙션 종류 |
|---|---|---|---|
| S1 | **한 선(One Line)** | Hero 다이어그램의 엉킨 선이 한 선으로 정리된 뒤 화면 밖으로 나가지 않고 **왼쪽 진행 레일이 되어 페이지 끝까지** 내려간다. 스크롤에 비례해 그려지고(scrub), 섹션 괘선을 지나 문의 섹션에서 플래그로 끝난다. 다이어그램·진행 표시·괘선이 한 획 | 로드 선 그리기 + scrub |
| S2 | **로고가 페이지를 감싼다** | 헤더 = 로고 윗줄 `Prologue`, 푸터 = 아랫줄 `— & —`. 로드 시 `&`가 워드마크에서 떨어져 S1 선의 **현재 위치 마커**가 되고, 스크롤 끝에서 푸터의 두 가로선 사이에 내려앉아 로고가 다시 완성된다. 진행 레일 점을 `&` 하나로 대체 | S1과 같은 scrub |
| S3 | **"& ___" 빈칸을 프로젝트가 채운다** | Projects 행 제목 `& Por favor, Harry`, Case Study 캡션·문서 제목·OG `Prologue & {프로젝트명}`, 서랍 헤더 `Prologue & 당신의 업무` → 첨부 시 `Prologue & {프로젝트명}`, 접수됨 `&` 크게 + "여기서부터 함께합니다" | 텍스트만 |
| S4 | **북엔드** | Hero와 문의가 같은 레이아웃·Display 형식, 색만 반전(bone ↔ navy). Hero 다이어그램의 끝 플래그가 문의 섹션에서 **새 선의 시작점**으로 다시 나타나 문의 버튼을 가리킨다(End → And). 레일 라벨 `Prologue · 01 · 02 · &` | — |

작은 것: 푸터 캡션 "Prologue& — and, 그리고 end. 처음과 끝을 함께합니다." / 로고 호버 시 `&` 면분할 선 그리기 + 양옆 가로선 늘어남 / Case Study 레일 01 "처음"·10 "끝", 다음 링크 `& 다음 이야기` / 404 "이 장은 아직 쓰이지 않았습니다" / 탭 제목 Home `Prologue&`, Case Study `Prologue & {프로젝트명}`, 서랍 열림 `Prologue & 당신의 업무`.
넣지 않음: 헤드라인 타이핑·단어 순환, 페이지 넘김 효과, 커스텀 커서, 섹션별 등장 애니메이션.
