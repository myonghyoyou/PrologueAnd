# 홈페이지 요청서 만들기 (`/tools/brief`) — 설계 명세

- 작성: 2026-10-15
- 근거 조사: `docs/tools/2026-10-15-homepage-brief-research.md`
- 화면 시안(사용자 승인): `data/images/tools/brief-{q5,q11,result}-{phone,pc}.png` (커밋하지 않음)

## 1. 무엇을 만드는가

홈페이지를 맡기려는 사장님이 질문 13개에 답하면, **어느 업체에나 보낼 수 있는 중립 요청서**와 그 요청서로 받은 견적을 비교하는 표가 나오는 도구. prologueand.com 안의 한 페이지.

**왜:** 기존 도구 32곳은 업체 편(그 업체 문의 유입·플랫폼 안에서만 쓰임)이고, 사장님이 들고 다른 업체에 보낼 요청서를 만들어 주는 국내 도구는 없다. 의뢰자 불만 1위는 소유권, 2위는 같은 요청인데 견적이 몇 배 차이(비교 불가), 5위는 무엇을 요청할지 모름 — 모두 처음 요청서로 줄일 수 있다.

**Prologue&에 주는 것:** 쓸모 있는 실물로 Prologue&를 알리는 입구(사용자 원칙: 나누는 도구는 그 일에서 제일 좋은 도구여야 한다). 요청서를 다 만든 사장님에게만 눈에 띄지 않게 「Prologue&에도 보내 볼 수 있어요」 한 줄.

**성공 기준:**
- 처음 온 사장님이 가입·연락처 없이 휴대폰으로 5~8분 안에 요청서를 끝낸다.
- 결과 요청서만 받고도 업체가 페이지·기능·명의·범위를 오해 없이 읽을 수 있다(조사 3절 필수 15항목을 모두 담음).
- 「Prologue&에도 보내기」를 누르기 전까지 답이 어디로도 전송되지 않는다(테스트로 확인).

## 2. 확정된 결정 (사용자)

## 3. 질문 흐름

공통 규칙:
- 모든 질문에 「모르겠어요」. 그렇게 답했거나 건너뛴 항목은 요청서 「업체 제안을 받고 싶은 것」에 모인다.
- **필수는 Q1(어떤 곳)·Q2(주 목적) 두 개뿐.** 나머지는 비워도 다음으로 넘어간다.
- 「견적에 크게 영향」 표시는 누르면 이유가 펼쳐진다(hover 말풍선 쓰지 않음). 이유 문장에 금액을 쓰지 않는다. 「2~4배」처럼 조사 근거가 있는 배수만 쓴다.
- 말투: 사이트와 같은 「~요」 존댓말. 낫표 쓰지 않음, 사이트 문구 규칙(docs/21)·금지 낱말 검사 대상.

## 4. 결과물

### 4-1. 결과 화면(사장님만 봄)

순서:
1. **요청서** — 제목 `홈페이지 제작 요청서 · {name 또는 '이름 미정'}`(Pretendard 굵게 — 사이트 세리프 Bodoni Moda는 라틴 글자만 있어 한글 제목에 쓰지 않는다), 부제 `새로 만들기|지금 홈페이지 고치기 · YYYY년 M월 D일 작성`. 단원: 무엇을 위한 홈페이지인가요(어떤 곳·손님이 할 일·주로 보는 사람) / (고치기) 지금 홈페이지 / 페이지 / 기능(꼭·나중에 표시, 이어 답) / 이어져야 하는 것 / 글과 사진 / 디자인 자료 / 디자인과 참고 사이트(좋은 점·메모) / 오픈 뒤 운영(관리자 화면 필요 여부) / 명의와 소유권 / 범위와 비용 약속 / 일정·결정 / (넣기 켰을 때만) 예산 / 업체 제안을 받고 싶은 것.
2. **견적을 크게 움직이는 항목** — §3 「견적 영향」에 걸린 답만, 각 이유 한 줄. 없으면 「크게 움직이는 항목이 없어요」.
3. **업체에 꼭 물어볼 질문** — 항상 나오는 4개 + 답에 따라 붙는 질문(§4-4).
4. **받은 견적 비교** — 업체 3곳(이름·금액 입력) × 행: 견적 금액 / 꼭 필요한 기능 포함 / 도메인 내 이름 / 소스·파일 받음 / 수정 횟수 / 매달 비용 / 오픈 가능일. 칸은 예·아니요·직접 입력. 그 기기에만 저장, 요청서·복사 글·PDF에 들어가지 않음. 따로 인쇄하지 않는다(화면에서만 봄).
5. **내보내기** — PDF로 저장(주 단추) · 글자로 복사 · 답 고치기 · 모두 지우기(확인 한 번).
6. 안내 한 줄: 「입력한 내용은 이 기기에만 저장돼요. 연락처는 묻지 않아요.」
7. 맨 아래 작은 회색 줄: 「이 요청서를 Prologue&에도 보내 볼 수 있어요 · 보내기」.

### 4-2. PDF(인쇄)
- `@media print`: A4, 검은 글자, 고정 머리글(`header.module.css` `.hdr{position:fixed}`)·`InquiryDrawer`·`ZoomViewer`(레이아웃이 모든 페이지에 붙임) 숨김, 위쪽 여백 0, 요청서 + 업체에 꼭 물어볼 질문(「이 요청서로 견적을 주실 때 아래 질문에도 답해 주세요」 안내 문장)만. 머리글·바닥글·단추·비교표·견적 영향·Prologue& 줄은 숨김. Prologue& 표시 없음.
- **앱 안 브라우저(쓰레드·인스타그램 등):** 구현 첫 단계에서 시험 페이지로 `window.print()` 동작을 실제 기기에서 확인한다(§9). 막혀 있으면 앱 안 브라우저를 감지해 「Safari나 Chrome으로 열면 PDF로 저장할 수 있어요」 안내를 띄우고 「글자로 복사」를 주 단추로 올린다.

### 4-3. 글자로 복사
카톡·문자에 붙일 일반 텍스트. 요청서 단원 제목 + 핵심 답, 업체에 물어볼 질문. 2,000자 안. Prologue& 표시 없음. 복사 후 「복사했어요」 한 줄 표시(접근성: `aria-live`). `navigator.clipboard`가 없거나 실패하면 글을 읽기 전용 글상자로 펼쳐 전체 선택해 두고 「길게 눌러 복사해 주세요」 안내.

### 4-4. 업체에 꼭 물어볼 질문 규칙

| 예약 | 예약은 어떤 방식으로 만드시나요? (네이버 연결이면 「네이버 예약은 어떻게 연결하시나요?」) |
| 결제 | 결제 수수료와 결제 서비스 가입은 누가 하나요? |
| 외국어 | 외국어 글 번역도 포함인가요? |
| 글·사진 대행 | 글 작성·사진 촬영 비용은 견적에 들어 있나요? |
| 고치기 + 옮길 양 보통 이상 | 지금 홈페이지의 글과 사진을 옮기는 것도 포함인가요? |
| 꼭 지켜야 하는 날 | 이 날짜까지 오픈이 가능한가요? 늦어지면 어떻게 하나요? |

### 4-5. Prologue&에도 보내기
- 결과 화면 링크를 누르면 `document.dispatchEvent(new CustomEvent('inquiry:open', { detail: { project: '', prefill } }))` — 기존 처리기가 `d.project`를 읽으므로 빈 문자열을 함께 보낸다.
- `prefill = { need: mode==='새로'?'새로 만들고 싶어요':undefined, pain: briefSummary(answers) }` — 고치기는 서랍의 기존 선택지(「쓰던 시스템을 고치고 싶어요」는 업무 시스템용 문구)와 맞지 않아 비워 두고, 요약 머리에 「지금 홈페이지 고치기」를 적는다. — `pain`은 1,000자 이하(서버 스키마 max). 요약은 `[요청서 만들기]` 머리 + 어떤 곳·주 목적·꼭 필요한 기능·페이지 수·희망일.
- 문의 서랍(`components/inquiry-drawer.tsx`)은 열릴 때 `detail.prefill`이 있으면: ① 단계를 step1로 돌린다(지금은 다시 열려도 이전 단계를 유지 — `:44`), ② 「지금 상황」 칸이 비어 있으면 요약을 넣고, 이미 글이 있으면 그 아래 한 줄 띄워 덧붙인다(사용자가 쓴 글을 지우지 않음). 서버가 `pain`을 1,000자까지만 받으므로(`lib/inquiry-schema.ts`, 서랍 글 칸엔 제한 없음) 합계가 1,000자를 넘으면 요약을 남은 길이에 맞춰 줄이고 끝에 「…」, 남은 길이가 100자 미만이면 덧붙이지 않는다, ③ `need`가 있으면 그 라디오를 고른다(이미 고른 게 있으면 두기). 폼은 비제어라 DOM 값으로 넣는다. `prefill`이 없으면 지금과 완전히 같다. 서버(`/api/inquiry`, `lib/mail.ts`)는 바꾸지 않는다.

- **시작 화면(저장된 답이 없을 때만):** 제목 「홈페이지 요청서 만들기」, 한 줄 소개, 세 가지 약속(5분 안팎 · 가입·연락처 없이 · 답은 이 기기에만 저장), 중립 선언 「특정 업체를 추천하거나 연결하지 않아요」, 견본 요청서(가상 가게), 「시작하기」. 저장된 답이 있으면 지금처럼 하던 곳에서 바로 이어진다. 모두 지우기 뒤에는 시작 화면.
