## 1. 무엇을 말하는 편인가

1차 시스템은 요청이 들어올 때마다 화면을 한 장씩 따로 만들어 붙였다. 기능은 쌓였지만 공통 규칙이 없어 화면마다 색·크기·틀이 달랐고, 새 화면을 더할수록 차이가 커졌다. 고도화의 핵심은 **색·버튼·입력칸 높이·화면 틀·아이콘을 공통 규칙으로 먼저 정하고, 22개 화면에 그 규칙을 적용한 것**이다.

다시 설계한 계기(사용자 확인): 고도화 요구가 계속 들어왔고, 서비스를 키우려면 디자인 시스템 같은 체계가 먼저 자리 잡아야 했다. **현업에서 들은 말은 없다** — 사용자 불만·연령을 지어내지 않고, 캡처에서 잰 사실로만 문제를 보인다.

참고 사례(조사, 2026-09-29): Linear 리디자인 글(부분 확대에 표시선), Stripe 대시보드 사례(전·후 크게, 컴포넌트 시트), Toptal·ABB 디자인 시스템 사례(규칙 시트). 끌어서 비교하는 슬라이더는 실제 에이전시 페이지에서 확인되지 않았고, 빽빽한 화면에서는 글자가 읽히지 않아 쓰지 않는다.

## 3. 문구

### 3-1. 이 편의 문구 기준 (docs/21 과 Por favor, Harry 개정에서 가져옴)

1. 표지: 윗줄은 프로젝트 이름만. 제목은 **무엇인지**, 소개 한 줄은 **문제**. 소개는 표지 그림 폭 한 줄(기존 규칙). 역할·기간 정보 표 없음.
2. R13 변신 슬로건 금지 — "~을 하나로", "~에서 ~로", "하나의 규칙으로", "끝이 시작".
3. R6 "A가 아니라 B" 는 이 편에서 01 인용 한 곳만.
4. R10·R19 은유·의인화 금지 — "화면이 멀어진다", "표가 말한다", "시선이 머문다".
5. R12 본문·캡션·핫스팟·표지 번호 설명은 끝맺은 문장. 조각은 제목과 표·시트의 라벨에서만.
6. R4·R5 평소 말로 — 사용자 → 쓰는 사람, 컨트롤 → 입력칸·버튼, 밀도 → 한 화면에 들어오는 행 수, KPI → 요약 숫자, 토큰 → 쓰지 않음, 대비 → 글자와 바탕의 명암 차이. "디자인 시스템"은 03 도입에서 "공통 규칙(디자인 시스템)" 으로 한 번, 그 뒤는 "규칙".
7. R18 낱말 돌려쓰기 금지 — "규칙"은 화면을 만드는 공통 규칙에만, "화면"은 시스템의 한 페이지에만, 그림은 "캡처".
8. R11 같은 틀 반복 금지 — 04 의 "전에는" 여섯 줄은 문장 끝을 섞는다.
9. R20 메타 설명 금지 — "이 장에서는 ~를 보여 줍니다" 없음.
10. 사실만 — 수치는 manifest 에 커밋과 함께 기록된 실측과 캡처에서 잰 값만. 캡처는 실제 화면에서 이름을 가린 것이라 "재현"·"가상" 표시를 붙이지 않는다.
11. R8 금지어 — 혁신·완벽·최적·직관적인.
12. `alt` 는 캡처 속 글자를 적힌 그대로(예: "매칭완료", "심사 대기").
13. manifest 의 작업 용어("라벨-값 2열", "토큰 색", "KPI 카드", "E안" 등)를 옮겨 적지 않는다.

### 3-2. 문구 초안

**목록 한 줄 소개**(`projects.ts` tagline): 22개 화면에 같은 색·버튼·표 규칙을 적용했습니다

**표지**
- 제목: `병원 자산·재고·인사 업무를<br>처리하는 사내 시스템`
- 소개: 기능이 늘 때마다 화면을 따로 만들어, 같은 시스템인데 화면마다 색과 버튼 크기가 달랐습니다.
- 그림: 재고관리 1차 화면 한 장에 번호 셋. 번호 설명(그림 아래 3열):
  1. 제품 정보가 세로로 쌓여 행 하나가 104px, 한 화면에 8행입니다.
  2. 한 행의 기능 버튼이 다섯 가지 색입니다.
  3. 검색칸과 도구 버튼 높이가 28px부터 40px까지 섞여 있습니다.
- `alt`: 재고관리 1차 화면. 가운데 위에 제목과 검색칸이 있고, 연두색 표 머리 아래 행마다 제품 정보가 여러 줄로 쌓여 있으며, 오른쪽 기능 칸에 색이 다른 버튼 다섯 개가 놓여 있다.

**01 문제** — 제목: 화면마다 색과 크기를 따로 정했습니다
- 문단 1: 재고와 비품은 원래 양식이 다른 엑셀 파일 여러 개로 관리했습니다. 이를 시스템으로 옮긴 뒤에도 재고, 출고, 의료소모품, 직원명부처럼 요청이 들어올 때마다 화면을 하나씩 더했습니다.
- 문단 2: 색과 크기는 화면을 만들 때마다 그 자리에서 정했습니다. 화면이 늘수록 제목 위치, 표 머리 색, 버튼 모양이 화면마다 달라졌습니다.
- 표(캡처에서 잰 값, 2026-09-29):

| 재고관리 | 가운데 | 연두 #D7F3D4 | 5 |
| 출고내역 | 가운데 | 연파랑 #DBE4F6 | 4 |

## 4. 새 블록

### 4-1. 번호를 찍은 한 장 — 표지 그림

- 타입: `cover.hero` 에 세 번째 종류 `PinnedHero = { pinned: Figure; pins: { x: number; y: number; text: string }[] }` 를 더한다(기존: 캡처 한 장 `Figure`, 어느 하루 판 `ScatterHero`). `x`·`y` 는 캡처 대비 %.
- 모양: 캡처 한 장(기존 Frame 규칙: 1px bone-900 틀 + 안쪽 6, 원본 픽셀보다 크게 그리지 않음) 위에 지름 30 남색(navy-800) 원 번호, 둘레 4px 옅은 남색 고리. 그림 아래에 번호 설명을 3열(폰 1열)로 — 번호 원 22 + 설명 15px.
- 번호와 설명은 `aria-describedby` 로 잇지 않고, 설명 목록을 캡처 바로 뒤의 순서 목록(`<ol>`)으로 둔다(읽는 순서 = 번호 순서).
- 표지 소개 문단 폭 = 캡처 틀 폭(기존 규칙).

### 4-2. 화면별 차이 표 — 01

- 타입: `TableBlock = { type: 'table'; cols: string[]; rows: Cell[][]; foot?: Cell[]; caption?: string }`, `Cell = string | { swatch: string; text: string }`. `foot` 은 맨 아래 비교 줄(굵게, 위 괘선 bone-900).
- 모양: 본문 칸(body) 폭, 머리줄 아래 1px bone-900, 행 사이 1px bone-200, 머리줄 13px 굵게 bone-600. 색 칸은 14×14 견본 + 이름 + 옅은 hex(13px bone-500). 숫자는 tabular-nums.
- 값: 3-2 의 표 그대로(캡처에서 잰 값).
- 폰: 표를 `overflow-x:auto` 상자에 넣는다(본문은 넘치지 않는다).

### 4-3. 규칙 시트 · 적용 한 쌍 — 03

**규칙 시트** — `SheetBlock = { type: 'sheet'; rows: SheetRow[]; caption?: string }`
- `SheetRow = { rule: string; before: SheetCell; after: SheetCell }`, `SheetCell = { label: string; show: Show }`.
- `Show` 는 다섯 가지 중 하나(한 칸에 하나):
  - `{ swatches: { hex: string; name: string }[] }` — 28×28 견본 + 이름 12px
  - `{ crop: Crop }` — 자른 캡처(아래 자르기 규칙)
  - `{ heights: number[] }` — 높이 막대(폭 64, 높이 = 값 px, 가운데 "Npx")
  - `{ buttons: { text: string; kind: 'primary' | 'secondary' | 'danger' }[] }` — 32px 버튼 견본(After 캡처의 색·모서리를 따른다)
  - `{ frame: string[] }` — 목록 화면 틀 그림(칸마다 이름: 제목·소속 / 도구줄 / 표 / 쪽 번호)
- 모양: 넓은 칸(wide) 폭, 1px bone-900 틀. 행마다 규칙 문장(15px 굵게)이 두 칸을 가로지르고, 그 아래 왼쪽(전, bone-50 바탕)·오른쪽(후, bone-0 바탕) 두 칸, 가운데 1px bone-900 세로선. 행 사이 1px bone-200. 칸 머리에 "전 · 1차 화면에서 뽑음" / "후 · 정한 규칙"(13px bone-500) 한 번.
- 폰: 행마다 전 위, 후 아래.

**적용 한 쌍** — `RuleBlock = { type: 'rule'; h: string; p?: string; before: Crop; after: Crop }`
- 모양: 왼쪽 여백 칸에 제목(h3)·설명, 오른쪽 그림 칸에 전·후 자른 캡처를 나란히(각 위에 "전"·"후" 13px 라벨). 폰은 위아래.

**자르기**(`Crop = Figure & { crop: { x: number; y: number; w: number; h: number } }`, 원본 대비 %)
- 파일을 새로 만들지 않고 화면에서 영역만 보인다 — 틀 비율 = (w·원본폭):(h·원본높이), 안의 이미지 폭 = 100/w × 100%, 위치 = (−x/w, −y/h) × 100%.
- 자른 영역이 원본 픽셀보다 크게 그려지지 않게 폭 상한 = w·원본폭 + 틀 여백.
- 좌표 초안(시안에서 확인, 구현 때 다시 확인):
  - 재고관리 기능 칸 세 행: 전 (81, 28, 19, 24) · 후 (81.5, 22, 16.5, 17)
  - 출고상세 버튼 줄: 전 (33, 69, 42, 9)
  - 묶음 목록 윗부분: 전 (10.5, 0, 89.5, 30)
  - 왼쪽 메뉴: 전 (0, 0, 10.5, 60) · 후 (0, 0, 11.5, 60)

### 4-4. 전/후 전환 — 04 여백 주석

- 모양: 그림 틀 위 오른쪽에 "후 · 전" 두 단추(높이 28, 1px bone-300, 누른 쪽 bone-900 바탕·bone-50 글자 — 헤더 현재 위치 표시와 같은 반전). 기본 후. 누르면 같은 틀 안에서 전 캡처로 바뀐다(.2s 페이드, 모션 줄이기는 즉시).
