## 1. 지금 구조와 문제

지금은 대시보드(`v6/index.html`) 안의 `#sheet`가 `v3/projects.html?embed=1`을 iframe으로 띄우고, 상세(`case.html`)는 그 iframe 안에서 페이지 이동으로 연다. `html.embed`일 때 페이지 헤더·상단바·푸터를 숨기고 시트 헤더(← Projects / Prologue & 제목 / ×)가 그 역할을 대신한다.

| 문제 | 원인 |
|---|---|
| 목록·상세가 좁다. 상세의 라이브 화면(1280 기준)이 0.6배 아래로 줄어든다 | 시트 폭 56rem(896px) |
| 커서가 화살표↔I빔으로 떨렸다(2026-09-21 수정) | 부모 문서가 매 프레임 다시 그리는 위에 iframe이 있음 |
| 시트 헤더와 페이지 헤더가 둘. 제목·뒤로가기를 부모가 iframe 안을 들여다보며 맞춘다 | 두 문서를 하나처럼 보이게 하는 접착 코드(`sheetTitle`, `sheetBack`) |
| 브라우저 뒤로가기가 시트를 닫지 않고 iframe 안 이력을 움직인다 | iframe 이력이 부모 이력에 섞임 |
| 주소가 없다. 상세를 링크로 보낼 수 없다 | 시트는 URL이 아님 |

## 2. 목표와 원칙
1. 목록·상세가 화면을 다 쓴다. 헤더 64px 아래가 전부 내용.
2. 헤더는 대시보드와 **같은 것**으로 보인다(브랜드 왼쪽, 메뉴 오른쪽). 페이지가 바뀌어도 헤더는 움직이지 않는다 — S2(로고가 페이지를 감쌈).
3. 목록 → 상세 전환(docs/20 A 제목 공유 + D 번호 레일)은 유지.
4. 대시보드로 돌아오면 Projects 점(`#p06`)에 서 있고 인트로는 다시 나오지 않는다.
5. 상세는 주소를 가진다(`case.html?p=slug`). 브라우저 뒤로가기가 기대대로 움직인다.
6. 시트에서 승인된 밀도(행 16px 상하·28px 좌우, 번호 레일 애니메이션, 상세 항목 간격)를 잃지 않는다.

## 3. 안 비교

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A 전면 레이어 | `#sheet`를 100vw × 100vh로 키우고 iframe 유지. 대시보드 헤더가 위에 남고 레이어는 그 아래 | 바꿀 곳이 CSS 몇 줄. 대시보드가 밑에 살아 있어 닫으면 즉시 제자리 | iframe·접착 코드·이력 문제가 그대로. 주소 없음. 커서 떨림 재발 여지 |
| **B 페이지 이동** | 시트를 없애고 `projects.html`·`case.html`을 **그 자체로** 연다. 문서 간 View Transition으로 헤더는 고정, 내용만 바뀜 | 그릇이 하나(브라우저). 주소·뒤로가기·스크롤 복원이 공짜. 접착 코드 삭제. 실제 제품(라우트 `/projects`, `/projects/{slug}`)과 같은 구조 | 대시보드를 다시 읽음(폰트·GSAP은 캐시, 세계 그리기 <100ms). 대시보드→목록 전환은 문서 간 VT 지원 브라우저에서만 애니메이션(Chrome 126+, Safari 18.2+; Firefox는 즉시 전환) |
| C 같은 문서 주입 | 목록·상세 HTML을 fetch해 대시보드 문서 안 레이어에 넣음 | 한 문서라 어떤 전환도 가능 | 두 페이지의 CSS·JS(Lenis, 번호 레일, morph, 라이브 iframe)를 대시보드와 한 문서에서 공존시켜야 함. 목업 단계에서 가장 큼 |

**권장 B.** "화면에 꽉 채운다"는 요구는 A로도 되지만, 그러면 시트의 문제(iframe·이력·주소)를 화면만 키운 채 안고 간다. B는 목업에서도 제품에서도 같은 그림이고, 바꾸는 양은 A보다 크지만 지우는 코드가 더 많다. C는 지금 필요 없다.

## 4. 화면 설계 (B 기준)

### 4.1 진입점 (대시보드)
| 자리 | 지금 | 바뀜 |
|---|---|---|
| 헤더 메뉴 Projects | `data-sheet` → 시트 | `<a href="../v3/projects.html">` |
| 판 6 "Projects 보기" 버튼 | `data-sheet` | 같은 링크 |
| 푸터 `.ft` Projects | `data-sheet` | 같은 링크 |
| 시작 판 "작업 보기 →" | `data-go="6"` (점 6으로 이동) | 그대로. 목록으로 바로 가지 않고 판 6에서 한 번 멈춘다 |

`#sheet`, `#sheet-bd`, `V.openSheet/closeSheet/sheetTitle/sheetBack`, 키 입력의 시트 가드, 시트 CSS는 삭제.

### 4.2 Projects 목록 (`v3/projects.html`)
```
┌ 헤더 64 ─────────────────────────────────────────────┐
│ Prologue&                          [Projects] [문의]  │  Projects는 현재 위치: 테두리 없음·navy-800·클릭 안 됨
├──────────────────────────────────────────────────────┤
│  (상단 여백 40)                                       │
│  Projects                                             │  h1
│  지금까지 한 일. 이름 뒤의 빈칸을 채워 온 것들입니다.       │  lead
│  ─────────────────────────────────────────────────    │
│  01  Por favor, Harry                                  │  행: 번호 40 + 본문, 상하 16 · 좌우 28 (시트 밀도 그대로)
│      #흩어진 요청 · 2025 · 대표                          │
│      업무 요청을 한 줄로 받는 창구                        │
│  ─────────────────────────────────────────────────    │
│  02  …                                                 │
│                                                        │
│  푸터: Projects · hello@prologue.and · 문의 · © 2026    │  대시보드 `.ft`와 같은 행. 문서 끝에 정적으로
└──────────────────────────────────────────────────────┘
```
- 폭: 읽기 폭 **max-width 56rem**, 가운데. 시트와 같은 폭이라 밀도가 그대로 옮겨진다. 화면이 넓어도 행을 늘리지 않는다(행이 길어지면 제목과 한 줄 설명 사이가 멀어진다).
- 좌우 여백은 헤더 브랜드 시작선(`padding-left 112px`)에 맞추지 않고 가운데 정렬. 헤더는 화면 폭, 내용은 읽기 폭 — 대시보드 판과 같은 관계.
- 필터 탭 없음, 이미지 없음, "N건 · 날짜 기준" 없음(기존 결정).
- 번호 레일 없음(목록은 짧다).

### 4.3 Case Study 상세 (`v3/case.html`)
```
┌ 헤더 64 ─────────────────────────────────────────────────────┐
│ Prologue& Por favor, Harry     ← Projects   03 / 10   [문의]   │
├──────────────────────────────────────────────────────────────┤
│  Prologue & Por favor, Harry · 문제 01 흩어진 요청     역할 …   │  case-head (상단 여백 40)
│  흩어진 업무 요청을 하나의 흐름으로                    기간 …   │  h1 = 공유 요소 pj-title
│  ┌──────────────────────────────────────────────┐              │
│  │ 라이브 화면 (1280 기준, 폭에 맞춰 축소)          │              │  읽기 폭 64rem이면 0.8배 — 시트(0.6배)보다 크다
│  └──────────────────────────────────────────────┘              │
│  01 ─ │ 01 Overview …                                          │  번호 레일 sticky, 도착 후 01→10 그려짐(D)
│  02 ─ │ 02 Problem …                                            │
│  …    │                                                         │
│       │ 다음 이야기 → Daeryun Learning Hub                       │
│  푸터                                                           │
└──────────────────────────────────────────────────────────────┘
```
- **상단바(`.topbar`)를 없애고 헤더 하나로 합친다.** 헤더 왼쪽은 `Prologue&` + 제목(`.who`, 시트 헤더에서 쓰던 형식), 오른쪽은 `← Projects` · `NN / 10` · `문의`. "이 프로젝트 보고 문의하기" 버튼은 헤더에서 빼고 10번 항목(비슷한 문제가 있다면)의 버튼만 남긴다 — 헤더에 버튼 둘은 많다.
- 읽기 폭 **64rem**. 라이브 화면·표는 이 폭, 본문 문단은 `.cs` 안에서 44rem.
- 번호 레일: 지금 시트에서 쓰는 방식(항상 표시, 도착 0.3s 뒤 01→10 40ms 간격) 그대로. sticky top 88px.
- morph(전·후 비교) 블록: 시트에서 정적(`#morph-stick{position:static}`)으로 바꾼 것이 승인된 상태 → 그대로 정적. 220vh 스크롤 고정 버전은 버린다.
- 마지막 "다음 이야기" 링크 → 다음 상세로 같은 전환.

### 4.4 돌아가기
| 어디서 | 동작 | 결과 |
|---|---|---|
| 상세 헤더 `← Projects` | 목록에서 왔으면 `history.back()`, 아니면(직접 진입) `projects.html` | 목록의 스크롤 위치와 클릭했던 행이 복원되고 제목이 제자리로 내려온다(docs/20) |
| 목록·상세의 브랜드 `Prologue&` | `../v6/index.html#p06` | 대시보드 Projects 점에서 시작, 인트로 없음 |
| 브라우저 뒤로가기(목록에서) | 대시보드 `#p06` | 같음. 대시보드가 이력에 `#p06`을 남겨 두므로 그 자리 |
| Esc | 아무 일도 없음 | 페이지에는 Esc가 없다(문의 서랍이 열려 있을 때만 서랍 닫기) |

브랜드가 인트로로 가지 않고 `#p06`으로 가는 이유: 목록에서 브랜드를 누르는 사람은 "방금 있던 곳"을 기대한다. 인트로는 주소를 직접 쳤을 때만.

### 4.5 모바일 (<1024)
- 지금도 시트가 100vw × 100vh였으니 보이는 결과는 거의 같다. 헤더 56px, 목록 좌우 16px, 상세 번호 레일 숨김(기존 규칙).
- 대시보드 모바일 미리보기(`?mob=1`)는 그대로.

## 5. 전환 (docs/20 확장)

| 구간 | 헤더 | 내용 | 시간 |
|---|---|---|---|
| 대시보드 → 목록 | 고정(`view-transition-name: hdr`, 양쪽 문서 같은 이름) | 대시보드 150ms 페이드 아웃 → 목록 250ms 페이드 인 + 8px 상승 | 350 |
| 목록 → 상세 | 고정 | A 제목 공유(350ms) + D 번호 레일(0.3s 뒤 0.66s) | 기존 |
| 상세 → 목록 | 고정 | 제목이 행으로 내려옴 | 기존 |
| 목록 → 대시보드 | 고정 | 목록 150ms 아웃 → 대시보드 250ms 인. 카메라는 이미 점 6 | 350 |

- 구현은 지금과 같은 **문서 간 View Transition**(`@view-transition { navigation: auto }`)을 대시보드 문서에도 켠다. 헤더는 세 문서에서 같은 마크업·같은 높이·같은 메뉴 스타일이어야 "안 움직인 것"으로 보인다 → §7의 헤더 통일이 전제.
- 진행 지도(`.pmap`)는 대시보드에만 있다. 헤더가 공유 요소면 진행 지도가 갑자기 사라지는 게 보인다 → 진행 지도는 헤더 밖 형제 요소로 빼서(같은 자리에 absolute) 내용과 함께 페이드.
- 지원 안 하는 브라우저(Firefox)는 즉시 전환. `prefers-reduced-motion`이면 전환 없음(기존).
- 대시보드 문서에서 VT를 켜면 `pageswap`에서 카메라 위치가 URL 해시(`#p06`)로 남아 있으므로 돌아올 때 그대로 복원된다. 대시보드 자체의 매 프레임 렌더는 VT 캡처와 무관(VT는 이동 직전 한 프레임만 찍는다).

## 6. 주소와 상태
| 화면 | 목업 | 제품(예정) |
|---|---|---|
| 대시보드 | `v6/index.html#p0n` | `/#p0n` |
| 목록 | `v3/projects.html` | `/projects` |
| 상세 | `v3/case.html?p={slug}` | `/projects/{slug}` |

- `sessionStorage('vt-slug')`(돌아올 행) 유지. `?embed=1`은 더 쓰지 않는다(코드는 한 번에 지우지 않고 목록·상세가 전면으로 옮겨진 뒤 삭제).
- 스크롤 복원: `history.scrollRestoration = 'auto'`(기본). Lenis가 켜진 페이지는 `pageshow`에서 Lenis에 위치를 알려 준다.

## 8. 수용 기준
a. 대시보드 헤더 Projects → 목록이 화면 전체에 뜨고, 헤더는 위치·크기·메뉴가 그대로(한 픽셀도 움직이지 않음).
b. 목록 행 밀도가 시트 때와 같다(행 상하 16px, 좌우 28px, 제목 20px).
c. 행 클릭 → 상세: 제목이 행에서 상단 H1 자리로 이동(A), 번호 레일 01→10이 0.3초 뒤 순서대로 그려짐(D).
d. 상세의 라이브 화면 축소 배율이 시트 때(≈0.6)보다 크다(64rem 폭에서 ≈0.8).
e. 상세 `← Projects` → 목록의 스크롤 위치·클릭했던 행이 그대로, 제목이 행으로 내려옴.
f. 목록의 브랜드 또는 뒤로가기 → 대시보드가 Projects 점(`#p06`)에서 인트로 없이 열림. 축소 토글 상태 유지(localStorage).
g. 상세 주소를 새 탭에 붙여 넣으면 상세가 단독으로 열리고 `← Projects`는 목록으로 간다.
h. 목록·상세 어디서도 커서 떨림 없음, 문의 서랍은 세 화면에서 같은 위치·같은 동작.

## 9. 자체 검토

**심각**
1. **헤더 통일이 먼저.** 세 문서의 헤더가 조금이라도 다르면(v3 메뉴는 밑줄 링크, v6는 테두리 버튼) 공유 요소 전환에서 헤더가 두 번 그려지거나 메뉴가 형태를 바꾸며 튄다. → v3.css 헤더 규칙을 v6 스타일로 바꾸고, 세 문서 헤더 마크업을 같은 순서로.
2. **대시보드 상태 재구성.** 페이지 이동이므로 v6 JS가 다시 실행된다. 해시 `#p06`로 위치는 복원되지만 판 등장 상태(`.show`)·점 켜짐·잉크 길이는 `render()` 한 번으로 재계산되어야 한다. 지금 코드는 `hi > 0`이면 `anim.pos = T[i]`로 놓고 `intro(skip=true)` → `render()`이므로 된다. 확인 항목으로 둔다.
3. **Lenis + 문서 간 VT.** 목록·상세는 Lenis 세로 스크롤. `pageswap` 시 Lenis가 스크롤 위치를 바꾸면 캡처 프레임이 어긋난다 → 전환 직전엔 Lenis를 건드리지 않고, `pagereveal` 뒤에 `lenis.scrollTo(scrollY, {immediate:true})`로 맞춘다.

**확인**
4. 대시보드→목록 전환에 `&` 마커 연출(마커가 헤더 브랜드의 `&` 자리로 날아감)을 넣을지. S2에 맞는 장치지만 지금 마커는 숨김 상태(선 관통 문제 미결)라 이번엔 뺀다.
5. 상세 헤더에서 CTA 버튼("이 프로젝트 보고 문의하기")을 빼는 것. 10번 항목의 버튼과 서랍의 `data-project` 연결은 유지.
6. 목록 읽기 폭 56rem, 상세 64rem — 서로 다르다. 목록은 행이 짧아야 하고 상세는 화면이 커야 해서 다르게 두지만, 헤더 브랜드 시작선과 맞추지 않는 대신 가운데 정렬이 어색하지 않은지 넓은 화면(1920)에서 볼 것.
7. GitHub Pages·로컬 서버 모두 경로가 상대(`../v3/…`)라 그대로 동작. `file://`에서는 문서 간 VT가 동작하지 않지만 이동은 된다.

## 10. 순서
1. 헤더 통일(v3.css ← v6 메뉴 스타일, 세 문서 마크업 정렬) — 다른 변경 없이 먼저 커밋해 헤더만 검수.
2. `html.embed` 규칙 승격 + `.topbar` → 헤더 합침(목록·상세를 단독으로 열어 검수).
3. 대시보드 시트 삭제 + 링크 교체 + 문서 간 VT 켜기.
4. 돌아가기(브랜드 `#p06`, `← Projects` 이력 우선) + 수용 기준 a~h 확인.
5. `embed` 코드·`?embed=1` 삭제, docs/22 §5·compare.html 갱신.

### 11.3 규칙
- 한 화면에 움직이는 것은 하나. D3(03~05)와 D5(07)는 겹치지 않는 구간이고, D2의 잉크는 배경처럼 조용히 내려온다(1.5px, 색 변화 없음).
- 스크롤 비례(D2·D3·D5)는 `lenis.on('scroll')` 한 곳에서 `t`를 계산해 나눠 준다. `IntersectionObserver`는 D6 한 곳(08 진입)만.
- `prefers-reduced-motion`: D2 잉크·D3·D5·D6 모두 **최종 상태 즉시**(After·정리된 선·그려진 막대). D1·D4·D7·D8은 그대로(움직임이 아니라 상태).
- 터치: D4는 탭 토글, D3·D5는 네이티브 스크롤로도 동작(Lenis `syncTouch:false`). 좁은 화면(<1024)은 D2 레일 숨김(기존), D3은 sticky 해제하고 Before/After 두 장 정적.
- 모든 값(고정 구간 160vh, 와이프 120vh, 막대 0.6s)은 시안에서 손본다.

### 11.4 데이터가 필요한 것
- D4 핫스팟: 프로젝트마다 화면 위 영역 3개의 좌표(1280×800 기준 %)와 캡션 — `V3.projects`에 `spots:[{x,y,w,h,cap}]` 추가. 지금은 Por favor, Harry만 라이브 화면이 있으니 나머지 프로젝트는 핫스팟 없이 화면만.
- D6 막대: 전·후 값 두 개(`impact:[{label, before, after, unit}]`). 지금 Impact 3개(4→1, 0회, 1곳)는 값이 있으니 그대로 쓴다.
- D5: Before 화면이 있는 프로젝트만(지금은 Por favor, Harry). 없으면 07을 After 한 장으로.
