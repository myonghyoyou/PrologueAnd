### 3.2 스트립 패널 — D2 합본형 N장 + 표제 1장 + 꼬리 1장

| # | 패널 | 폭 | 내용 | 도형 |
|---|---|---|---|---|
| 0 | 표제 | 44vw | 괘선 + `01` + "이런 문제를 이렇게 풀었습니다" / 캡션 "오른쪽으로 넘기세요 →" / "02 일하는 방식으로 →"(건너뛰기) | 없음 (선만 지나감) |
| 1 | `& Por favor, Harry` | 84vw, **max 1280px** | 헤드라인(프로젝트명, Display) / 왼쪽 아래 **문제 블록**(`문제 01 & 흩어진 요청` + 한 줄) / 오른쪽 스크린샷(16:10 매트) / "Case Study →" | **흩어진 원 4개**(navy-100 면) → 선 위에서 하나로 모이는 미니 다이어그램 |
| 2 | `& 병원 UI/UX 고도화` | 〃 | 같은 구성 · 문제 02 불편한 시스템 | **격자**(navy-100 사각 다수) → 정돈된 3열 |
| 3 | `& Daeryun Learning Hub` | 〃 | 같은 구성 · 문제 03 종이·수작업 | **종이 두 장**(navy-100 + bone-0 사각, 1px 테두리) → 한 흐름 |
| 4 | `& Custom Commerce` | 〃 | 같은 구성 · 문제 04 아이디어 | **고리**(navy-100 굵은 원) → 탐색→구매→주문→운영 5노드 |
| 끝 | 꼬리 | 24vw | "Projects 전체 보기 →" / "02 일하는 방식으로 →" | 선이 아래로 꺾임 |

- **N = `V3.featured().length`.** 패널·진행 칸·캡션 `01 / 0N`은 모두 이 값으로 생성한다. 하드코딩 4 금지. Notion 규칙 "대표는 정확히 4개"는 빌드 시 검증(4가 아니면 빌드 경고, 스트립은 N장으로 렌더)
- 패널 순서 = Notion `Order`. **스트립은 고정, 목록은 자란다** 규칙 유지(`11` §2)
- 헤드라인 크기는 V2 규칙 계승: 2줄 이하 7.8rem / 3줄 6.8rem / 4줄 이상 5.6rem — V2의 `wrapPanels()` 줄 수 판정(`.xl/.lg`)을 그대로 옮긴다. 1024px 폭(패널 860px)에서 `& Por favor, Harry`가 3줄로 떨어지는 경우를 이 규칙이 받는다. 서체 Pretendard 600, `&`만 Didone(S3)
- 패널 `max-width:1280px`: 1920px 화면에서 84vw = 1613px가 되어 헤드라인(고정 rem) 오른쪽이 비는 것을 막는다. 트랙 폭 = 패널 폭 합 + 간격이므로 pin 길이도 함께 줄어든다
- S3 조인 글리프: V3의 "문제 & 사례" 가운데 `&`는 합본 패널에서 자리가 없으므로, **문제 블록 캡션을 `문제 01 & 흩어진 요청`** 형식으로 두어 S3를 유지한다(14 §1 표의 "문제 & 사례" 항목은 이 표기로 개정, §6)
- 패널 클릭 → `/projects/[slug]` 페이지(V3). 가운데 시트(V2)는 쓰지 않는다

### 3.4 한 선(S1) — 3구간 사상
v3의 선 엔진은 "문서 y → 선 길이" 단조 사상(`geo.lenAt`)과 "선 끝 = scrollY + 50vh" 규칙 위에 서 있다. pin 구간에서는 scrollY가 늘어도 섹션의 문서 좌표가 멈추고 트랙이 가로로 움직이므로, 그대로는 성립하지 않는다. **선을 3구간으로 나누고 각 구간에 다른 사상을 둔다.**

| 구간 | 선이 그려지는 곳 | 선 끝(마커) 규칙 | 진행 변수 |
|---|---|---|---|
| ① 세로 위 | 페이지 절대 SVG: Hero 노드 → rail-x → 아래 → 스트립 진입점(스트립 상단 + 패널 중앙 높이 58%) | 화면 **y = 50vh** 고정 (v3와 동일) | scrollY (pin 시작 전) |
| ② 가로 | **트랙 안의 SVG**: 진입점 → 표제·패널 N장 관통 → 꼬리 | 화면 **x = 50vw** 고정, 트랙이 그 아래로 흐름. y는 진입점 높이 고정 | pin 진행도 p ∈ [0,1] = ScrollTrigger progress. 트랙 translateX = −p·(트랙 폭 − 100vw), 그려진 길이 = 진입점부터 화면 x=50vw까지 |
| ③ 세로 아래 | 페이지 절대 SVG: 이탈점(꼬리 패널에서 rail-x로 복귀) → 02 → 03 → 푸터 `— & —` | 화면 y = 50vh, 마지막 뷰포트에서 푸터로 달려감 (v3 규칙) | scrollY (pin 끝 이후) |

- ①의 끝점과 ②의 시작점, ②의 끝점과 ③의 시작점은 **같은 화면 좌표**가 되도록 진입·이탈 프레임에서 좌표를 맞춘다(수용 기준 §8-a)
- `&` 마커는 하나의 fixed 요소. 구간에 따라 위 규칙으로 화면 좌표를 계산한다
- 다크 구간 클리핑(`#line-dark`)·레일 라벨 위치·`geo.H`는 **pin-spacer가 삽입된 뒤** 좌표라야 맞는다 → `ScrollTrigger.refresh()` 완료 후 `build()`를 다시 실행하고, resize 때도 같은 순서
- 패널 n의 미니 다이어그램은 ②에서 선 끝이 그 패널의 도형에 들어오는 순간부터 그려진다(같은 p로 scrub)

### 3.5 pin·이동·진행
| 항목 | 값 | 근거 |
|---|---|---|
| pin 시작 | `start: "top top+=64"` — 헤더(고정 64px) 아래에 스트립 상단이 닿을 때. 진행 칸은 스트립 상단 24px 위치 → 헤더에 가리지 않음 | v3.css `.hdr` 64px |
| pin 길이 | 트랙 폭 − 100vw (`end: "+=" + (track.scrollWidth - innerWidth)`) | 세로 1px = 가로 1px |
| 관성 | Lenis lerp 0.1 그대로(세로가 부드러우면 가로도 같이). 별도 가로 lerp 없음 | `14` §3.6 |
| 휠 한 칸 | **§7-① 확인 후 확정.** 임시값 140px(V2 저장 기본값 `speed:1.4`). 1440px 화면에서 패널 피치 약 1226px → 140px이면 9칸, 100px이면 12칸 | `11` §7, `d-poster.html` TUNE |
| 속도 축소(zoom) | 없음 | `14` §4 |
| **현재 장 판정** | 패널 n의 **왼쪽 가장자리가 화면 x = 50vw를 지나는 순간** n장. 진행 칸과 패널 캡션이 같은 함수를 쓴다 | 두 표시가 어긋나지 않게 |
| 진행 표시 | 스트립 상단 **칸 N개**(현재 navy-800) + 패널 캡션 `0n / 0N`. 레일 라벨은 `01`만(부제 없음) | 14 원칙 1 — 표시 3중을 2중으로 |
| 건너뛰기 | 표제·꼬리 패널의 "02 일하는 방식으로 →" 버튼 = pin 끝 위치로 `scrollTo`. **키보드 규칙은 시안 범위 밖**(pin 구간에서 ↓는 곧 가로 이동이므로 "↓로 탈출"은 성립하지 않음) | §9 |

### 3.6 커서·호버
- 커스텀 + 커서는 **쓰지 않는다**(14 결정). 패널 호버 시 "Case Study →" 밑줄(signal), 스크린샷 매트 테두리 bone-900 → navy-800. 150ms
- 도형은 호버에 반응하지 않는다(놀이는 스크롤에만)

### 3.7 모바일 (≤1023px, v3의 `desktop()` 기준과 동일)
- pin·가로 이동 없음. 표제 → 패널 N장 → 꼬리를 **세로 스택**. 패널 높이 자동, 도형은 오른쪽 아래 축소, 스크린샷 전폭
- 선·마커 숨김(V3와 동일), 헤더 `01 / 04`
- `scroll-snap` 없음

### 3.8 reduced-motion

## 4. 기술 전제 (검토에서 바로잡은 것)
| 전제 | 사실 | 대응 |
|---|---|---|
| "Lenis + ScrollTrigger pin은 v2에서 검증됨" | **아니다.** v2·v3 어디에도 ScrollTrigger가 없다. v2 가로 이동은 자체 엔진(`main.cur/target`), v3는 Lenis 콜백으로 직접 계산 | pin은 이 프로젝트의 **첫 도입**. v4 1단계에서 스트립만 있는 최소 페이지로 pin+Lenis를 먼저 검증한 뒤 v3에 합친다 |
| GSAP 플러그인 | v3 `index.html`은 gsap 코어만 로드 | `ScrollTrigger.min.js`(jsdelivr 3.12.5) 추가 + `gsap.registerPlugin(ScrollTrigger)` |
| Lenis 구동 | v3는 자체 `requestAnimationFrame` 루프 | `gsap.ticker.add(t => lenis.raf(t * 1000))`, `lenis.on('scroll', ScrollTrigger.update)`, `gsap.ticker.lagSmoothing(0)`로 교체. `scrollerProxy`는 불필요(Lenis가 네이티브 스크롤 사용) |
| pin 방식 | — | `pinType: "transform"`이 아니라 기본(fixed)로 시작하고, Lenis와 떨림이 있으면 transform으로 전환. 둘 다 시험해 기록 |
