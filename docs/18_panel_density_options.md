## 1. 선(S1)과 `&`의 자리 — 3가지 (패널 안과 독립적으로 결정)

여백 띠의 절반은 "선 레인"에서 온다. 선 자리를 먼저 정해야 패널 안을 짤 수 있다.

| 안 | 선의 위치 | 글자와의 관계 | 장점 | 단점 |
|---|---|---|---|---|
| **L1 바닥선 (권장)** | 패널 높이 **80%**. 모든 패널의 "바닥" | 글자는 전부 선 위에. 다섯 단계 노드·문제 4항목은 선 **위에 올라앉는** 형태(선 = 밑줄·지면) | 레인 불필요, 판의 상단 80%를 통째로 쓸 수 있음. 히어로의 4경로 도형도 바닥에서 올라오는 그림이 됨 | 선이 화면 아래쪽에 있어 `&`의 존재감이 조금 줄어듦(58%→80%) |
| L2 헤드라인 밑줄 | 각 패널 헤드라인의 **베이스라인 바로 아래**(패널마다 다른 높이) | 선이 곧 밑줄. `&`는 글자 아래를 지나감 | 선과 글자가 한 몸으로 읽힘 — 가장 "편집물"다움 | 패널마다 선 높이가 달라 패널 사이에서 선이 계단으로 꺾임(곡선 연결 필요). 구현 복잡 |
| L3 현행 62% 레인 유지 | 지금 그대로 | 레인 48px 비움 | 변경 없음 | 여백 띠 그대로. 이 안은 여백 문제를 못 푼다 |

L1을 택하면 v5.js의 `LINE()`만 0.62 → 0.80으로 바꾸고 CSS의 `--ly` 기준 위치들을 "선 위에 올라앉음"으로 재배치한다.

## 2. 패널 안 — 5가지 안

### A. D 문법 완전 복원 — "문장 하나 + 도형 하나", 패널을 쪼갠다 (9장)
V2가 잘 됐던 이유를 그대로 가져온다. 정보를 줄여서 크게 쓴다.

| # | 패널 | 문장(줄바꿈 그대로) | 보조문 | 도형(navy-100 면, 글자를 덮음) |
|---|---|---|---|---|
| 00 | Prologue | 복잡한 업무를 / 단순한 제품으로 / 바꿉니다. (3줄 6.8rem — 5줄은 바닥선 위에 안 들어감, 시트에서 확인) | 만들기 전에 정리하고, 쓰이는 끝까지 함께합니다. | 4경로 곡선(왼쪽 가장자리 →) + 엉킨 원 3개 |
| 01 | 흩어진 요청 | 흩어진 / 요청 (7.8rem) | 엑셀·메신저·이메일·구두 요청으로 흩어진 업무 | **흩어진 원 4개** (`panels.js` circles) |
| 02 | 불편한 시스템 | 불편한 / 시스템 | 기능은 있는데 쓰기 어렵고 복잡한 화면 | **격자** (grid) |
| 03 | 종이·수작업 | 종이· / 수작업 | 그대로 옮기면 안 될 것 같은 디지털화 | **종이 두 장** (papers) |
| 04 | 아이디어 | 아이디어 | 구조와 화면이 아직 없는 제품 | **고리** (ring) |
| 05 | 다섯 단계 | 처음부터 / 끝까지. (7.8rem) | Understand · Simplify · Design · Build · Improve — 선 위의 노드 5개, 단어만 1.2rem | 원 5개(가운데 하나 navy-100 큰 원) |
| 06 | Projects | 작업 / 6건. (7.8rem) | 문제 유형별 Case Study → 시트 | 사각 6개 흩어짐 |
| 07 | 문의 | 지금 하시는 / 업무를 / 알려주세요. (6.8rem, navy 반전) | 이 페이지의 끝이 프로젝트의 시작입니다 · 2영업일 | 플래그 → 버튼 |
| 08 | — & — | (로고 아랫줄) | Prologue& — and, 그리고 end. | 없음(의도된 여백) |

- 문제 4장은 V2의 도형 4종을 `panels.js`에서 그대로 쓴다(이미 있음). 각 장 클릭 → Projects 시트를 그 유형 필터로 연다(`?type=`).
- 다섯 단계의 설명·칩은 노드 호버 라벨로 내리거나 뺀다.
- 스트립 9장 ≈ 7.5화면(V2 12장보다 짧고, 지금 6장보다 3장 김).
- **장점**: Rauno 밀도 그대로, 도형 재사용, 문제 유형이 큰 글자로 각인. **단점**: 넘기는 장 수 +3, 세부 정보(단계 설명·칩) 사라짐.
- 공수: 마크업 재작성(패널 9장), CSS 헤드라인 규칙, 도형 배치. `panels.js`·선 엔진 재사용. **중**

### B. 장 수 유지(6장), 글자·도형만 크게 — "포스터화"
지금의 6장 구성을 유지하되 각 장을 문장 하나 + 도형 하나로 압축한다.

| # | 패널 | 문장 | 나머지 |
|---|---|---|---|
| 00 | Prologue | 복잡한 업무를 / 단순한 제품으로 / 바꿉니다. (6.8rem) | 보조문 한 줄 + 버튼 2개(바닥선 위) + 4경로 곡선 |
| 01 | 문제 | 이런 문제를 / 다룹니다. (7.8rem) | 바닥선 위에 **단어 4개**(흩어진 요청 · 불편한 시스템 · 종이·수작업 · 아이디어)만 1.4rem, 설명문 삭제. 도형: 원·격자·종이·고리를 **작게 4개** 단어 위에 |
| 02 | 다섯 단계 | 처음부터 / 끝까지. (7.8rem) | 바닥선 위 노드 5개 + 영어 단어만. 소개문·설명·칩 삭제 |
| 03 | Projects | 작업 6건. (7.8rem) | 버튼 하나 |
| 04 | 문의 | 지금 하시는 / 업무를 / 알려주세요. (6.8rem) | 보조문 한 줄 + 버튼 + 플래그 |
| 05 | — & — | (로고 아랫줄) | 그대로 |

- **장점**: 스트립 길이 그대로, 수정 범위 작음(마크업 대부분 유지, CSS 크기·배치 변경). **단점**: 문제 유형·단계의 설명이 전부 사라져 "무슨 문제인지"는 시트에 가야 안다. 문제 4개가 한 판에 작은 글자로 남아 01은 여전히 상대적으로 약함.
- 공수: **소**

### C. 2단 포스터 — 큰 문장 + 좁은 정보 열
정보를 지키면서 밀도를 올리는 절충. 각 패널을 **왼쪽 62% 큰 문장(6.8~7.8rem) + 오른쪽 34% 작은 정보 열(13~15px)** 로 나눈다. 도형은 왼쪽 문장을 덮는다.

- 01 문제: 왼쪽 "이런 문제를 / 다룹니다." 오른쪽 열에 4항목(번호·이름·한 줄).
- 02 다섯 단계: 왼쪽 "처음부터 / 끝까지." 오른쪽 열에 5단계(이름·한 줄). 노드는 바닥선.
- 00·04: 왼쪽 문장, 오른쪽 열에 보조문·버튼.
- **장점**: 지금 있는 정보를 하나도 안 버림, 큰 글자로 판이 찬다. **단점**: 한 판에 두 문법(포스터 + 문서)이 공존 — 외부 피드백 "덧붙인 느낌"이 재발할 위험. 오른쪽 열은 여전히 작은 글자.
- 공수: **중**

### D. 콘텐츠 맞춤 가변 폭 — 판 크기를 내용에 맞춘다
글자를 키우는 대신 판을 줄인다. 히어로·문의는 84vw, 문제·Projects·& 는 44~56vw, 다섯 단계는 100vw. Rauno도 카드 폭이 일정하지 않다.

- **장점**: 빈 판이 사라지고 리듬이 생김(넓은 판·좁은 판 교대). **단점**: 사용자가 이미 "패널 크기 일치"를 요청했음(2026-09-16) — 그 결정을 되돌리는 안. 작은 글자 문제는 그대로.
- 공수: **소**

### E. 최소 변경 — 도형만 넣고 레인만 없앤다
타이포·구성은 그대로 두고, 6장 각각에 큰 navy-100 도형 하나를 글자 뒤에 깔고 선을 바닥선(L1)으로 내린다.

- **장점**: 반나절 작업. **단점**: 글자가 여전히 46px이라 "도형 뒤에 작은 글자" — 여백 인상의 절반만 해결. 임시 처방.
- 공수: **극소**

## 4. 추천
**L1 바닥선 + A(9장)**. 이유: 여백의 원인 세 가지(작은 글자·요소 과다·도형 없음)를 한 번에 없애고, V2에서 이미 검증된 도형 4종과 "문제 유형 포스터"를 그대로 살린다. 잃는 세부 정보(단계 설명·문제 설명)는 Projects·Case Study 시트가 맡는다 — 시트는 이미 있다.
차선은 **L1 + B**: 장 수를 늘리고 싶지 않다면.

A로 가면 순서: ① 선 바닥선(0.80) 전환 → ② 헤드라인 규칙 P1~P5 → ③ 문제 4장 분리 + 도형 → ④ 다섯 단계·Projects·문의 압축 → ⑤ 모바일 스택 확인 → 아티팩트 갱신.
