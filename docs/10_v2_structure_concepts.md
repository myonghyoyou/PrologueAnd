## 2. 공통 골격

### 2.1 페이지와 내비게이션
```
/              랜딩 — 브랜드·문제·사례·일하는 방식·문의가 전부 여기
/work          작업 목록 — Notion DB에서 읽음, GRID / LIST 토글
/work/[slug]   Case Study 상세 — Notion 본문 블록 렌더링
(전역)         문의 서랍 — 어느 화면에서든 한 번의 클릭으로 오른쪽에서 열림
```
- 헤더 요소는 셋뿐: 로고 · `Work` · `문의`. Home / Services / About 메뉴 없음
- Services·About 내용은 랜딩의 "일하는 방식"과 문의 서랍 안내문에 녹임
- `/contact`는 `/?contact=open` 리다이렉트(외부 링크용)

### 2.2 문의 서랍 (drawer)
- 오른쪽에서 슬라이드, 배경은 어둡게. 어느 화면에서든 열림
- 보던 프로젝트(Case Study)가 자동 첨부됨 — "Por favor, Harry를 보고 문의합니다"
- 폼은 PRD §6.2 그대로 2단계(문제 → 목표·연락처). 제출 후 같은 서랍 안에서 "접수됨"
- 컨셉 A에서는 방문자가 첫 화면에 입력한 문장이 폼 1번 필드에 미리 채워짐

### 2.3 데이터 — Notion DB
| 속성 | 유형 | 용도 |
|---|---|---|
| Title | 제목 | 프로젝트명 |
| Tagline | 텍스트 | 한 줄 메시지 |
| Problem | 선택(4개) | 랜딩의 문제 4개와 연결 — 흩어진 요청 / 불편한 시스템 / 종이·수작업 / 아이디어 |
| Tags | 다중 선택 | Workflow Design 등 |
| Role / Period | 텍스트 | Overview |
| Disclosure | 선택 | full / anonymized / mockup |
| Order | 숫자 | 노출 순서 |
| Published | 체크 | 공개 여부 |
| Cover | 파일 | 목록 썸네일 |
| (본문) | 블록 | Case Study 10단계를 H2로 구분 |

- Next.js에서 Notion API로 읽고 ISR(예: 1시간)로 캐시. 프로젝트 추가·수정은 Notion에서만
- 시안 단계에서는 같은 스키마의 JS 배열로 대체

## 3. 컨셉 3안

### 3.1 컨셉 A — 도구형 "사이트가 곧 제품"
**구조**: 첫 화면이 홈페이지가 아니라 하나의 도구. 방문자가 문제를 고르거나 입력하면 그 문장이 **요청 카드**가 되어 `접수 → 분석 → 재설계 → 제품` 4단계를 지나간다.

| 단계 | 화면 | 인터랙션 |
|---|---|---|
| 입력 | "지금 어떤 업무가 복잡한가요?" 입력창 + 문제 칩 4개 | 칩 클릭만으로도 진행 |
| 접수 | 입력 문장이 카드로 변해 큐에 들어감 | 카드 이동 모션 |
| 분석 | "비슷한 문제를 이렇게 풀었습니다" — Problem 속성이 일치하는 프로젝트가 붙음 | Notion DB 필터 |
| 재설계 | 그 프로젝트의 Before → After 다이어그램이 그려짐 | 다이어그램 scrub(단계 내 스크롤) |
| 제품 | 문의 서랍이 열리고 방문자 문장이 채워져 있음 | 서랍 |

- 진행은 스크롤이 아니라 **상태 전이**. Lenis는 Work·Case Study에서만
- 상단 진행 표시 = 4단계
- "그냥 둘러볼게요" 탈출구 → Work
- Work 목록은 심사 Queue와 같은 표 UI — 서비스(업무 시스템)를 사이트가 직접 시연
- 시각 언어: **제품 UI풍** — Pretendard, 밝은 회색 표면 `#F3F4F7` + 흰 패널, 네이비 액센트, 작은 모노스페이스 상태 라벨, 로고는 심볼 `P&` 위주
- 위험: 첫 화면이 입력을 요구해 이탈 가능 → 칩 클릭 즉시 진행, 탈출구 상시 노출

### 3.2 컨셉 B — 도면형 "한 장의 캔버스"
**구조**: 랜딩이 스크롤 페이지가 아니라 한 장의 도면. 중앙에 브랜드 문장, 왼쪽에 문제 4개, 오른쪽에 프로젝트 4개가 **선으로 연결된 노드**로 놓임.

- 휠·드래그로 도면 이동, 노드 접근 시 확대. 관성 이동은 자체 lerp(도면은 가상 스크롤이라 Lenis 미적용, Work·Case Study에는 적용)
- 문제 노드 클릭 → 연결된 프로젝트만 밝아짐. 프로젝트 노드 클릭 → 그 자리에서 확대되며 Case Study 패널이 열림
- 커서 십자선이 도면 좌표를 표시
- 일하는 방식 5단계는 도면 하단에 치수선처럼
- 첫 3초 동안 선이 그려지며 시선을 문제 → 프로젝트 순으로 유도
- Work 페이지 = 같은 도면에 Notion의 모든 프로젝트를 노드로 + LIST 토글
- **모바일은 도면을 포기**하고 세로 목록으로 폴백
- 시각 언어: **설계도풍** — 트레이싱지 `#F7F8FA`, 네이비 1px 선, 치수선·좌표, 헤드라인만 Didone. 로고 `&` 면분할이 노드 문법
- 위험: 발견 가능성 — 안내 애니메이션과 "처음이세요? 문제부터 골라보세요" 힌트로 보완

### 3.3 컨셉 C — 서사형 "선 하나가 관통한다"
**구조**: 섹션 구분·제목 없이 **선 하나**가 페이지를 위에서 아래로 관통. 선이 지나는 자리마다 문제 → 사례 → 방식 → 문의가 나타남.

| 구간 | 선의 상태 | 내용 |
|---|---|---|
| 도입 | 엉킨 4가닥(전화·메신저·이메일·방문) → 스크롤하면 한 가닥으로(scrub) | 브랜드 문장 고정, 단어가 스크롤에 따라 밝아짐 |
| 문제·사례 | 선 위의 매듭 4개. 매듭이 풀리면 사례 등장 | 문제 ↔ 프로젝트 쌍 |
| 방식 | 정거장 5개(핀 고정) | Understand … Improve + 고객 불안 즉답 칩 |
| 끝 | 선의 끝 = 삼각 플래그 = 문의 서랍 손잡이 | 서랍 |

- Lenis + GSAP ScrollTrigger. 모바일도 같은 구조
- Work 페이지 = 같은 선을 왼쪽 레일로 두고 Notion 목록
- 시각 언어: **편집물풍** — Didone + Noto Serif KR 헤드라인, 순백 바탕, 넓은 여백, 선은 검정 헤어라인, 끝의 삼각 플래그만 네이비
- 위험: 세 안 중 "스크롤 페이지"에 가장 가까움 → 섹션·카드·제목을 완전히 없애 차이를 만듦

### 3.4 컨셉 D — 포스터형 "패널을 넘긴다" (2026-09-15 추가)
**배경**: A·B·C를 본 사용자 피드백 — "Rauno를 참고했는데 전혀 Rauno 느낌이 아니다". 진단: Rauno에서 원칙(인터랙션 종류 축소, 가벼움, 진행 표시, 십자 커서)만 옮기고 **느낌**(포스터 구성)은 옮기지 않았다. Rauno의 느낌은 ① 한 화면에 단어 10개 이하 ② 거대한 평면 도형이 글자를 덮고 겹침 ③ 서체 하나를 아주 크게 ④ 가로로 넘기는 흰 패널 ⑤ 회색 바탕 위 종이 같은 패널 — 다섯 가지에서 나온다. A·B·C는 셋 다 "글을 읽는 사이트"이고 Rauno는 "포스터를 넘기는 사이트"다.

**구조**: 회색 바탕 `#ECEDF0` 위에 흰 패널 12장이 가로로 늘어서고 휠을 돌리면 옆으로 넘어간다(관성 이동, 키보드 ←→, 드래그). 상단 필름 스트립 진행 표시, 작은 십자(+) 커서. 패널 하나 = 문장 하나 + 도형 하나, 단어 12개 이하.

| # | 패널 | 문장 | 도형 |
|---|---|---|---|
| 01 | Prologue& | 복잡한 업무를 단순한 제품으로 바꿉니다. | 하늘색 낙서 덩어리가 글자 위를 덮음 |
| 02 | Prologue& | & 그 다음 장을 엽니다. | 거대한 네이비 삼각 플래그 |
| 03~06 | Problem 01~04 | 흩어진 요청 / 불편한 시스템 / 종이·수작업 / 아이디어 | 흩어진 원 4개 / 빽빽한 사각 격자 / 겹친 종이 2장 / 빈 고리 |
| 07~10 | Work 01~04 | 프로젝트명만 거대하게 | 그 프로젝트의 Before→After 선을 굵은 도형으로. 클릭 → Case Study 패널 |
| 11 | 일하는 방식 | 다섯 정거장. | 원 5개 + 단어 5개 |
| 12 | 문의 | 지금 하시는 업무를 알려주세요. | 네이비 패널 + 하늘색 플래그. 클릭 → 문의 서랍 |

- 서체 **Pretendard 하나**(500, 자간 -.035em, 행간 1.02). 세리프·모노 없음. 로고 워드마크만 세리프
- 색: 회색 바탕 / 흰 패널 / 검정 글자 / 네이비 / **하늘색 `#7DB6F2`**(로고 스틸블루를 밝힌 것, Rauno의 노랑 자리 — 사용자 결정)
- 문제 패널을 누르면 연결된 프로젝트 패널로 이동. Work = 07번으로 이동, 목록 = 공유 목록 패널
- 모바일: 패널을 세로로 쌓음
- **옷은 고정** — D는 Rauno 원형 재현이 목적이라 시각 언어 3종을 적용하지 않는다
- 파일: `design/mockups/v2/d-poster.html`, 허브에 D 버튼과 격자 행 추가

## 4. 시안 제작 범위 (제작 완료)

제작된 파일: `design/mockups/v2/index.html`(비교 허브), `a-tool.html`, `b-canvas.html`, `c-line.html`, 공통 `shared.js`(Notion DB 대역 데이터·문의 서랍·커서 십자선·진행 표시·Lenis·Work 목록·Case Study 본문·테마 전환), `shared.css`(테마 3종 정의 + 공통 구조).

**구조 × 시각 언어 = 9가지 조합.** 세 시각 언어는 `shared.css`의 `[data-theme="product|blueprint|editorial"]` 변수 세트로 정의되어 세 구조 파일이 정확히 같은 옷을 공유한다. 각 구조 파일은 색·서체를 하드코딩하지 않고 변수만 참조한다(정적 검사로 확인: 하드코딩 색 0개). `?theme=` 파라미터 또는 시안 하단 스위치로 전환하며, `index.html`의 "9개 한눈에" 모드가 3×3 격자로 첫 화면을 나란히 보여준다.

| | 제품 UI풍 | 설계도풍 | 편집물풍 |
|---|---|---|---|
| 배경 / 패널 | `#F3F4F7` / 흰 패널 + 회색 테두리 | `#F7F8FA` 트레이싱지 / 반투명 패널 + 네이비 테두리 + 코너 틱 | 순백 / 패널 없음, 검정 헤어라인 |

| 라벨 | JetBrains Mono | JetBrains Mono 대문자 | Bodoni 세리프 |
| 버튼 | 검정 채움, 4px 모서리 | 네이비 채움, 각진 모서리 | 검정 채움/윤곽, 각진 모서리 |

HTML 구조·JS 문법·자산 경로는 정적 검증 통과. 실제 렌더링·인터랙션 확인은 브라우저에서 진행 예정.
