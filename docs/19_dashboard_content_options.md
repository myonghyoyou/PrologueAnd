| 재료 | 출처 | 지금 스트립에 있는가 |

## 2. 스트립 내용 — 5가지 안

### A. "이름이 곧 구조" — Prologue · & · End 3막 (권장)
브랜드명의 뜻(처음과 끝을 함께)을 스트립의 뼈대로 쓴다. 5단계는 3막 안으로 흡수된다(Understand·Simplify = 처음 / Design·Build = 그리고 / Improve = 끝).

| # | 패널 | 문장 (7.8 / 6.8rem) | 보조문 한 줄 | 도형 | 선 위에서 |
|---|---|---|---|---|---|
| 00 | Prologue | 복잡한 업무를 / 단순한 제품으로 / 바꿉니다. | B2B Product Engineer — 만들기 전에 정리하고, 쓰이는 끝까지 함께합니다. | 엉킨 선 뭉치(navy-100 면) | 선이 **엉킨 뭉치에서 풀려 나와** 시작 (§3-S2) |
| 01 | **처음.** | 만들기 전에, / 무엇이 불편한지부터. | Understand · Simplify — 현재 업무를 이해하고 불필요한 단계를 걷어냅니다 | 큰 원 하나(비어 있음 = 시작) | 노드 "처음" |
| 02 | **그리고.** (`&` 크게) | Workflow, 화면, 제품을 / 한 사람이. | Design · Build — 설계와 구현이 한 손에서 이어져 처음 정리한 문제가 흐트러지지 않습니다 | Didone `&` 글리프를 도형 크기로(navy-100) | 노드 "&" |
| 03 | **끝까지.** | 출시가 끝이 아니라, / 쓰이는 데까지. | Improve — 사용 후 드러나는 문제를 반복해서 고칩니다 | 플래그(삼각) 크게 | 노드 "끝" + 플래그 |
| 04 | 누구를 위해 | 병원 · 제조 · 건설 · / 사내 시스템. | 개발 지식이 없어도 됩니다. 지금 쓰는 방식과 불편한 점만 알려주세요 | 사각 4개(업종) | — |
| 05 | 무엇을 | 고치거나, / 만들거나, / 시작하거나. | 기존 시스템 개선 · 업무의 웹 시스템화 · 아이디어 → MVP (서비스 3종) | 격자 → 정돈 | 노드 3개 |
| 06 | Projects | 작업 / 6건. | 문제 유형별 Case Study | 사각 흩어짐 | — |
| 07 | 문의 (끝) | 지금 하시는 / 업무를 / 알려주세요. | 이 페이지의 끝이 프로젝트의 시작입니다 | — | 플래그 → 버튼 |
| 08 | — & — | (로고 아랫줄) | Prologue& — and, 그리고 end. | — | `&` 착석 |

- **장점**: 스트립을 한 번 넘기면 이름의 뜻·일하는 방식·고객·서비스가 순서대로 읽힌다. "처음 / & / 끝"이 선 위의 노드가 되어 S2(로고가 페이지를 감쌈)와 이어진다. 9장 그대로.
- **단점**: 고객 문제 4유형이 스트립에서 사라진다(→ Projects 시트의 필터 탭이 담당). "그리고."가 한국어 문장으로는 약할 수 있음 → `&` 글리프를 헤드라인으로 쓰는 안(§4)과 함께 볼 것.

### B. "포지션 4요소" — Workflow × UX × Engineering × Automation
문제 4장을 **포지션 4요소** 4장으로 바꾼다. 나머지는 지금 구조 그대로.

| # | 문장 | 보조문 | 도형 |
|---|---|---|---|
| 01 | Workflow / Design. | 업무가 흐르는 순서를 다시 그립니다 | 선 4가닥 → 1가닥 |
| 02 | B2B / UX. | 매일 쓰는 사람이 읽는 순서대로 | 격자 → 3열 |
| 03 | Product / Engineering. | 설계한 대로 실제 제품으로 | 사각 블록 쌓임 |
| 04 | Automation / AI. | 반복 입력·집계는 사람이 안 하게 | 고리 → 직선 |

- **장점**: 수정 범위 최소(4장의 글·도형만 교체). "무엇을 하는 사람인가"가 4장으로 또렷.
- **단점**: 영어 전문 용어 4개 — 주 고객(비개발자)에게 `01` §8 "너무 좁음/추상적" 경고에 걸림. 이름의 뜻은 여전히 푸터에만.

### C. "서비스 3종" — 고객이 고를 수 있는 문 3개
문제 4장을 **서비스 3장**으로. `05` §5의 흐름(현황 분석 → … → Prototype)을 선 위 노드로.

| # | 문장 | 보조문 | 선 위 노드 |
|---|---|---|---|
| 01 | 있는 시스템을 / 고칩니다. | 기존 업무 시스템 UX·Workflow 개선 | 현황 → 진단 → 정보구조 → UX → Prototype |
| 02 | 업무를 / 시스템으로. | 엑셀·종이·메신저로 돌던 일을 웹으로 | 분석 → 설계 → MVP → 구현 |
| 03 | 아이디어를 / 제품으로. | 아이디어 → MVP | 구조화 → 범위 → UX → MVP |

- **장점**: 문의 전환에 가장 직접적(방문자가 "내 경우"를 고름). 선 위 노드가 서비스 절차가 되어 S1과 자연스럽게 맞음.
- **단점**: 판매 페이지처럼 보일 위험. 브랜드 서사(이름)는 약함. 3장이라 스트립이 8장.

### D. "방문자의 질문 4개" — 15의 질문 순서를 패널로
① 무엇을 하는가 → ② 내 문제도 풀어봤는가 → ③ 믿을 만한가 → ④ 어떻게 연락하는가. 각 질문이 헤드라인, 답이 보조문.

- **장점**: `15` §1의 논리를 그대로 스트립에 옮김. **단점**: 질문형 헤드라인은 포스터로는 약하고(문장이 길다), ②는 결국 프로젝트 이야기로 되돌아감.

### E. "복잡 → 단순" 순수 시각 서사
글을 최소화하고 선 자체가 이야기: 00에서 심하게 엉킨 선 → 장마다 조금씩 풀려 → 문의에서 직선 + 플래그. 각 장은 단어 하나(복잡 / 정리 / 설계 / 제품 / 단순).

- **장점**: 가장 Rauno답고 기억에 남음. **단점**: 정보가 거의 없어 B2B 방문자의 ①~③ 질문에 답하지 못함. 인상용 첫 5장 + A의 후반부를 합치는 변형은 가능.

## 3. 선의 시작점 — "하나의 흐름"을 대체할 5가지

지금: 왼쪽 가장자리에서 전화·메신저·이메일·직접 방문 4선이 모여 "하나의 흐름" 노드 → Harry의 도식. 브랜드 차원으로 바꾸는 안:

| 안 | 시작 모양 | 라벨 | 뜻 | 구현 |
|---|---|---|---|---|
| **S1 엉킴이 풀리며 시작 (권장)** | 패널 왼쪽에 **엉킨 선 뭉치**(navy-400 1px, 고리 몇 개 겹침)가 있고, 그 뭉치에서 **한 가닥이 빠져나와** 바닥선이 됨 | 뭉치 옆 "복잡한 업무", 선이 곧아지는 지점에 "단순한 제품" — 즉 브랜드 문장 그 자체가 라벨 | "복잡 → 단순"의 시각화. 특정 프로젝트가 아니라 브랜드 문장 | SVG 경로 1개(스크리블) + 로드 시 그리기. 지금 4경로 코드 교체 |
| S2 `&`가 그린다 | 시작점에 아무 도형도 없음. 로드 시 헤더에서 떨어진 **`&`가 착지하는 자리가 곧 시작점**, `&`가 오른쪽으로 가며 선을 그림 | 시작점 아래 작은 "Prologue" 캡션 하나 | "이야기의 시작은 &가 놓인 자리" — 이름의 뜻(And) | 가장 단순. 도형 없음이 단점(히어로가 가벼워짐) |
| S3 로고 워드마크에서 | 히어로 패널 안에 워드마크 `Prologue` 크게(Didone), 마지막 글자 `e`의 끝 획이 **그대로 선이 되어** 오른쪽으로 | 라벨 없음 | 로고가 선을 낳는다 — S2(로고가 페이지를 감쌈)와 가장 직결 | 워드마크를 SVG 텍스트로 두고 `e` 끝점 좌표에서 선 시작. 서체 의존 |
| S4 시작 노드 "처음" | 속이 빈 원(시작) + 캡션 "처음", 스트립 끝의 플래그 캡션 "끝" | 처음 / 끝 | 이름의 뜻(처음과 끝)을 두 끝점 라벨로 | 가장 작은 변경(라벨·노드만) |
| S5 여러 갈래 유지, 라벨만 브랜드로 | 지금처럼 4선이 모이되 라벨을 `업무 · 사람 · 화면 · 데이터`(또는 `요청 · 문서 · 습관 · 시스템`)로 | 하나의 제품 | "흩어진 것을 하나로"를 브랜드 일반론으로 | 라벨만 교체. 그러나 여전히 Harry 도식의 잔상 |

**권장 S1** — 도형(엉킴)과 문장(복잡 → 단순)이 브랜드 문장을 그대로 그린다. `&` 마커는 엉킴이 풀린 첫 지점에서 출발.

## 4. `&`를 패널 헤드라인으로 쓰는 것에 대해 (A안 02 보조 결정)
- A-02 "그리고."는 한국어로 약하다. 대안: 헤드라인을 **`&` 글리프 하나**(Didone, 패널 높이의 60%)로 두고 보조문에 "그리고 — Workflow, 화면, 제품을 한 사람이." 이 경우 `&`가 스트립에 세 번 등장(헤더 → 02 패널 → 푸터)해 S3(빈칸)·S2와 겹쳐 읽힌다.
- 다만 `&` 마커가 그 위를 지나가면 `&` 둘이 겹친다 → 02 패널에서만 마커를 헤드라인 `&` 안으로 "들어갔다 나오게"(마커가 헤드라인 `&`와 같은 자리에 오면 잠시 헤드라인이 채워짐) 하는 장치가 가능. 채택 시 상세 설계.
