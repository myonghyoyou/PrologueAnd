# Prologue& 프로젝트 Case Study 원천 자료

`Prologue&` 포트폴리오의 4개 프로젝트는 서로 다른 능력을 증명하도록 역할을 나눈다.

| 프로젝트 | 핵심 증명 |
|---|---|
| Por favor, Harry | Workflow Design / Product Thinking |
| Daeryun Learning Hub | Digital Transformation / Learning UX |
| 병원 UI/UX 고도화 | Enterprise UX / Legacy Improvement |
| Custom Commerce | End-to-End Product Engineering |

이 네 프로젝트를 합치면 다음 브랜드 메시지를 증명한다.

> **Prologue&은 기존 업무를 분석하고 → 구조와 UX를 설계하고 → 실제 작동하는 웹 제품까지 만드는 브랜드다.**

---

# 1. Por favor, Harry

## 핵심 메시지
> **업무 요청 관리 툴을 만들면서 가장 먼저 만든 것은 ToDo가 아니었다. 요청이 들어오는 구조부터 바꿨다.**

## 기존 문제
업무 요청이 다음 경로로 분산됨:
- 전화
- 메신저
- 이메일
- 직접 자리 방문

요청자는 자신의 요구를 충분히 정리하지 않은 상태로 전달하는 경우가 많았고, 요청을 받는 사람은 다시 정리하거나 기억해야 했다.

업무 중 전화와 대면 요청으로 몰입이 자주 끊겼다.

## 재설계
- 요청자별 개인 링크 제공
- 모든 요청을 하나의 Queue로 통합
- 요청 단계에서 필수 정보 구조화
- 심사 Queue에서 일괄 판단
- 수락 시 약속일 확정
- 진행 상태와 완료 여부 자동 공유

## 핵심 Insight
> **ToDo 관리의 문제가 아니라 요청 Workflow의 문제였다.**

## 포트폴리오에서 보여줄 것
- Before/After Workflow
- 요청폼
- 심사 Queue
- 진행 상태
- 약속일
- Dashboard
- 요청자 측 조회화면

# 2. Daeryun Learning Hub

## 핵심 메시지
> **1,220문항의 종이 문제집을 웹으로 옮기면서 가장 먼저 버린 것은 종이의 구조였다.**

## 기존 문제
- 행정직군 약 720문항
- 기술직군 약 500문항
- 매년 인쇄 후 폐기
- 문제와 정답이 분리
- 휴대 불편
- 틀린 문제 관리 어려움
- 오타 수정 어려움

## 재설계
기존:
> 문제 → 문제 → 문제 → 정답지

변경:
> 문제 → 답변 → 즉시 채점 → 해설/재도전 → 다음 문제

추가:
- 직군별 문제
- 모바일 학습
- 풀이 이력
- 오답관리
- 문제 수정 및 변경이력
- 팀 경쟁
- 명예의 전당

## 핵심 Insight
> **Digitization ≠ Copy**

디지털 전환은 기존 매체를 그대로 복제하는 것이 아니라, 그 매체 때문에 존재했던 제약을 제거하는 과정이다.

# 3. 병원 UI/UX 고도화

## 핵심 역할
Enterprise/B2B UX 역량을 보여주는 대표 사례.

## 포트폴리오 메시지
> **기능이 많은 업무 시스템도 사용자가 더 빠르게 읽고 처리할 수 있도록 정보구조와 화면 흐름을 다시 설계할 수 있다.**

## 강조할 관점
- 업무자가 실제로 어떤 순서로 정보를 읽는지
- 정보 밀도
- 정보 위계
- 입력폼 배치
- 가독성
- 사용자 연령 및 숙련도
- 기존 디자인 시스템 유지
- 기능은 유지하면서 Workflow 개선

## 준비할 자료
- 개선 전 화면 5~10개
- 개선 후 대응 화면
- 각 화면의 목적
- 사용빈도
- 주요 사용자
- 개선 전 문제
- 변경 이유
- 현업 피드백
- 정량 성과가 있다면 관련 수치

## Before/After 추천 유형
1. 정보밀도
2. 정보 위계
3. 업무 동선
4. 검색/입력 Form
5. 고령 사용자 가독성

## 핵심 Insight 후보
> **업무 시스템 UX에서는 예쁨보다 Scanability와 업무 맥락이 먼저다.**

# 4. Custom Commerce

## 핵심 역할
기성 쇼핑몰 솔루션에 의존하지 않고 실제 서비스 전체를 설계하고 구현할 수 있음을 증명.

## 포트폴리오 메시지
> **아임웹 등 완성형 쇼핑몰 프레임워크 없이 상품 탐색부터 주문·운영까지 필요한 Product Flow를 처음부터 설계하고 구현했다.**

## 먼저 정리해야 할 실제 구현 범위
- 상품
- 옵션
- 카테고리
- 검색/필터
- 장바구니
- 회원/로그인
- 주문
- 결제
- 배송
- 주문상태
- 관리자
- 상품관리
- 재고
- 쿠폰
- 리뷰
- 취소/환불
- 모바일
- SEO
- Analytics

※ 실제 구현한 기능만 최종 Case Study에 포함한다.

## 강조할 포인트
- 왜 기성 솔루션이 아닌 직접 구축이 필요했는가
- 전체 서비스 흐름을 어떻게 나눴는가
- 사용자 영역과 관리자 영역을 어떻게 설계했는가
- 어떤 기술적/제품적 의사결정을 했는가
- Custom Build의 장점과 Trade-off

## 핵심 Insight 후보
> **쇼핑몰은 상품페이지 하나가 아니라 탐색 → 구매 → 주문 → 운영이 연결된 하나의 Product Flow다.**
