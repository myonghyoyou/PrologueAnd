## 1. 어떤 웹인가 (먼저 정한 것)

**방문자**: 병원·제조·건설·사내 시스템 담당자, 개발 지식 없음, 카톡·Threads 링크로 모바일에서 처음 봄, 상사에게 링크를 공유함.
**방문자의 질문 순서**: ① 이 사람은 무엇을 하는가 → ② 내 문제와 비슷한 걸 풀어봤는가 → ③ 어떻게 일하는가, 믿을 만한가 → ④ 어떻게 연락하는가.
**사이트의 일**: 이 네 질문에 **이 순서대로, 스크롤 한 번으로** 답하고, 어디서든 한 번의 클릭으로 문의에 닿게 한다.

그래서 구조는 **세로 스크롤 한 장 랜딩**이다. 가로 포스터(D2)는 인상은 강했지만 ②를 찾는 방문자에게 "몇 장을 넘겨야 내 문제가 나오는지" 알 수 없었고, 모바일에서는 결국 세로였다. 세로 한 장은 방문자의 질문 순서와 같고, 진행 레일로 위치를 알 수 있으며, 공유·검색·인쇄에 유리하다. Rauno에서 남기는 것은 "한 화면에 말 하나"와 "종류가 적은 인터랙션"이지 가로 넘김이 아니다.

## 2. 사이트맵

```
/                      Home — 4개 질문에 답하는 세로 한 장
/projects              Projects — 전체 목록, 문제 유형 필터
/projects/[slug]       Case Study — 프로젝트 하나의 상세(고유 URL, 공유·검색용)
(전역)                 문의 서랍 — 어느 화면에서든 열림, 보던 프로젝트 첨부
/contact               → /?contact=open
```
헤더 요소: 로고 · Projects · 문의. About·Services 페이지 없음(Home 3·4번 섹션이 대신함).

## 3. Home

| # | 섹션 | 방문자 질문 | 구성 요소 (위→아래) | 높이 감각 |
|---|---|---|---|---|
| 1 | **Hero** | 무엇을 하는가 | Display 문장("복잡한 업무를 **단순한 제품**으로 바꿉니다.") / 리드 "만들기 전에, 무엇이 불편한지부터 정리합니다. 그리고 쓰이는 끝까지 함께합니다." / 1차 버튼 "프로젝트 문의" + 2차 "작업 보기" / 오른쪽에 **히어로 다이어그램**(엉킨 4선 → 한 선 → 플래그, 로드 시 그려짐) | 100vh |
| 2 | **문제 → 사례** | 내 문제를 풀어봤는가 | 섹션 헤더(괘선 + 01 + "이런 문제를 이렇게 풀었습니다") / **행 4개**: 왼쪽 = 문제(제목·한 줄 상황), 가운데 `&` 글리프(연결), 오른쪽 = 대표 프로젝트(제목·태그·결과 2줄·스크린샷 소·Case Study 링크). 행 전체가 링크 | 행당 약 40vh |
| 3 | **일하는 방식** | 믿을 만한가 | 섹션 헤더(02) / 5단계 가로 스텝(Understand…Improve), 단계마다 고객 불안 즉답 칩. 첫 단계에 "처음", 마지막 단계에 "출시 후에도" 칩 / 아래 3줄 소개("B2B Product Engineer…") + 잘 맞는 일 목록 | 60vh |
| 4 | **문의** | 어떻게 연락하는가 | 반전(navy-950) 섹션. Hero와 같은 Display 형식으로 호응(처음 ↔ 끝). Display 한 문장("지금 하시는 업무를 알려주세요.") / 리드 "이 페이지의 끝이 프로젝트의 시작입니다. 2영업일 안에 답변." / 1차 버튼(서랍 열기) / 이메일 직접 표기 | 70vh |
| — | 푸터 | — | 로고 아랫줄 `— & —`(두 가로선 + 앰퍼샌드) 가운데 / 캡션 "Prologue& — and, 그리고 end. 처음과 끝을 함께합니다." / Projects · 이메일 · 저작권 한 줄. 헤더가 `Prologue&` 윗줄, 푸터가 아랫줄 — 페이지가 로고를 처음과 끝으로 나눠 가짐 | — |

- **진행 레일 = 한 선(S1·S2)**: Hero 다이어그램에서 이어진 선 하나가 왼쪽에 고정되어 스크롤에 비례해 그려지고, 로고에서 떨어져 나온 `&`가 현재 위치 마커. 라벨 `Prologue · 01 · 02 · &`, 클릭 이동. 페이지 끝에서 `&`가 푸터의 두 가로선 사이에 도착. 모바일에서는 숨기고 헤더에 "02 / 04"
- 2번 행에는 스크린샷을 넣지 않는다(2026-09-16): 도형 + 미니 다이어그램 + 결과 숫자(`14` §3.5). 대표 4개만(`Featured`). 나머지는 Projects로 — "스트립 고정, 목록은 자란다" 규칙 유지
- 섹션 2 끝에 "Projects 전체 보기 →" 링크 1개

## 4. Projects

| 구성 요소 | 내용 |
|---|---|
| 페이지 헤더 | H1 "Projects" / 리드("문제 유형별로 정리한 작업 기록") / 건수 |
| 필터 | 탭 5개: 전체 · 흩어진 요청 · 불편한 시스템 · 종이·수작업 · 아이디어 (URL 쿼리 반영) |
| 목록 | **행**(카드 아님): 번호 · 제목(H2, `& {프로젝트명}` 형식 — S3) · 태그 · 연도 · 결과 1줄 · 스크린샷 소(16:10 매트). 대표는 "대표" 캡션. 호버 시 행 배경 bone-100 |
| 빈 상태 | 필터 결과 0건: "이 유형의 작업은 준비 중입니다. 비슷한 문제가 있다면 문의해 주세요" + 서랍 버튼 |
| 정렬 | Notion `Order`. 미공개(`Published` false) 제외 |

## 5. Case Study (`/projects/[slug]`)

| 구간 | 구성 요소 |
|---|---|
| 상단 고정 바 | 뒤로(Projects) · 프로젝트명 · **"이 프로젝트를 보고 문의"** 버튼(서랍, 프로젝트 첨부) |
| 헤더 | 캡션 `Prologue & {프로젝트명}`(S3, 문서 제목·OG도 같음) / 문제 태그 / H1(한 줄 메시지) / 메타 표: 역할 · 기간 · 사용자 · 공개 범위(full/anonymized/mockup) |
| 대표 이미지 | 스크린샷 1장, 매트 안에. alt에 Before/After 차이 |
| 본문 10단계 | 왼쪽 번호 레일(01~10, 현재 단계 채움, 클릭 이동. 01과 10은 "처음"·"끝" 캡션) / 오른쪽 본문. 03 Existing Workflow와 05 Redesign은 **같은 다이어그램 좌표계**에 위·아래 → 스크롤에 따라 Before가 After로 변형(scrub). 07 Before & After는 스크린샷 쌍, 사이에 `&` 글리프. 08 Impact는 숫자 2~3개 크게 |
| 하단 | 10 CTA(서랍) / `Built with` 한 줄 / 이전·다음 프로젝트 링크(`& 다음 이야기`) |
| 상태 | 공개 범위가 mockup이면 이미지 위에 "재구성 화면" 캡션 |

Notion 매핑은 `10` §2.3 그대로(H2 10개 = 10단계).

## 6. 문의 서랍 (전역)

- 트리거: 헤더 "문의", Hero 1차 버튼, 섹션 4 버튼, Case Study 상단 바·10단계 CTA, `/contact`
- 서랍 헤더: `Prologue & 당신의 업무`, 첨부 시 `Prologue & {프로젝트명}`(S3). 탭 제목도 같이 바뀜
- 1단계(현재 업무): 업무 / 도구(체크 칩) / 불편한 점 / 사용자 수 / 반복 빈도 / 기존·신규 → 2단계(목표·일정·예산·이메일) → 접수됨(같은 서랍 안, "여기서부터 함께합니다" + 답변 시점 안내)
- 첨부 표시: "Prologue & Por favor, Harry" 형식 + "이 프로젝트를 보고 문의합니다" + 해제
- 숨김 필드: 유입 경로, 참조 slug, 제출 시각. 서버로 이메일 + Sheets(PRD §6.3)
- 실패: 원인 + 이메일 주소 직접 표기. 열려 있는 동안 배경 스크롤 잠금, Esc·배경 클릭으로 닫힘

## 7. 모바일 (≤760px)

- Hero: 문장 → 다이어그램(축소) → 버튼 2개 세로
- 문제→사례 행: 문제(위) → 프로젝트(아래) 세로 스택, 스크린샷은 전폭
- 5단계: 세로 목록. 진행 레일 숨김, 헤더에 "02 / 04"
- Projects 필터: 가로 스크롤 탭. 행은 스크린샷 → 제목 → 태그 순
- Case Study: 번호 레일 → 상단 고정 바 안의 "03 / 10"
- 서랍: 전체 화면

## 8. 상태·오류·빈 화면 (공통)
- 이미지 로드 실패: 매트 안에 프로젝트명 텍스트
- Notion 미응답: 빌드 시점 캐시 사용(ISR), 목록 상단에 "최근 갱신 시각"
- 404: "이 프로젝트는 아직 공개되지 않았습니다" + Projects 링크

## 9. 동선 목표
- 첫 화면 → 문의 서랍: **1클릭**(Hero 버튼)
- 첫 화면 → 내 문제와 같은 사례: **스크롤 1~2회**(섹션 2)
- Case Study → 문의: 상단 바 상시 **1클릭**
