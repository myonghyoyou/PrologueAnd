# Prologue& 마케팅 전략

## 1. 목적

마케팅의 목표는 단순히 '개발 외주를 받는다'가 아니다.

> **Prologue&의 Product Thinking을 시장에 노출하고 → 어떤 문제에 사람들이 반응하고 돈을 내는지 확인하고 → 반복되는 문제를 향후 SaaS 후보로 발전시키는 것**

---

## 2. 브랜드 중심 원칙

모든 채널은 각각 별도의 브랜드처럼 운영하지 않는다.

- 포트폴리오
- 블로그
- Threads
- 크몽
- 향후 SaaS

모두 **Prologue&**이라는 하나의 브랜드 아래 연결한다.

권장 표기:
> **Prologue& — 복잡한 업무를 단순한 제품으로 바꿉니다.**

---

## 3. 채널 역할

### Prologue& 포트폴리오
신뢰와 전환의 중심.

역할:
- 무엇을 해결하는 브랜드인지 설명
- 실제 사례 증명
- 문의 유도

### 블로그
긴 Case Study와 Product Thinking을 축적하는 신뢰 자산.

역할:
- 검색 유입
- 전문성 증명
- 포트폴리오 보강

### Threads
발견과 반복 노출.

역할:
- 짧은 Product Insight
- Before/After
- 프로젝트 제작 과정
- 블로그/포트폴리오 유입

### 크몽
구매 의도가 있는 사용자의 전환 채널.

역할:
- 서비스 상품 판매
- 포트폴리오 기반 신뢰 형성
- 초기 고객 문제 수집

---

## 4. 핵심 판매 서비스

### 서비스 A
**기존 업무 시스템 UI/UX 및 Workflow 개선**

타깃:
- 기능은 많지만 쓰기 어려운 업무 시스템
- ERP
- 관리자 시스템
- 병원
- 제조
- 건설
- 사내 시스템

### 서비스 B
**종이·엑셀·메신저 기반 업무의 웹 시스템화**

타깃:
- 반복 수작업
- 엑셀 관리
- 카톡/메일 중심 진행
- 업무 상태 추적 어려움

### 서비스 C
**아이디어 → MVP 기획·설계·개발**

타깃:
- 아이디어는 있으나 제품 구조가 없는 고객
- 빠른 MVP가 필요한 팀/개인

초기 크몽에서는 2개 정도만 우선 판매한다.

---

## 5. 콘텐츠 전략

콘텐츠 비중 권장:
- Product/Workflow Insight: 40%
- 실제 Case Study: 30%
- Build in Public: 20%
- 직접 서비스 홍보: 10%

---

## 6. 프로젝트별 콘텐츠 메시지

### Por favor, Harry
메시지:
> **ToDo를 만든 것이 아니라 요청 Workflow를 바꿨다.**

대표 콘텐츠:
- 업무 요청 관리 시스템을 만들며 ToDo보다 먼저 고친 것
- 진행상황 문의를 줄이는 방법
- 요청자가 먼저 요구사항을 정리하게 한 이유

### Daeryun Learning Hub
메시지:
> **종이를 웹으로 복사하지 않고 학습경험을 다시 설계했다.**

대표 콘텐츠:
- 1,220문항 문제집을 웹으로 옮기며 버린 구조
- 디지털 전환은 PDF 만들기가 아니다
- 즉시 채점이 학습 UX를 바꾸는 이유

### 병원 UI/UX
메시지:
> **업무 시스템에서는 예쁜 화면보다 빠르게 읽고 처리하는 것이 중요하다.**

대표 콘텐츠:
- 사내 시스템을 소비자 앱처럼 만들면 안 되는 이유
- 고령 사용자에게 필요한 것은 큰 글씨만이 아니다
- 업무 시스템에서 여백을 늘렸는데 더 불편해질 수 있는 이유

### Custom Commerce
메시지:
> **기성 솔루션 없이 전체 서비스 Flow를 설계하고 구현했다.**

대표 콘텐츠:
- 쇼핑몰을 직접 만들며 가장 먼저 고민한 것
- 상품페이지보다 먼저 설계해야 하는 주문 Flow
- 관리자 화면이 중요한 이유

---

## 7. 콘텐츠 재활용 구조

하나의 프로젝트 경험을 여러 채널로 변환한다.

> Work Log  
> → Case Study  
> → 블로그 글  
> → Threads 5~10개  
> → 크몽 Portfolio  
> → 짧은 Portfolio 카드  
> → 서비스 CTA

마케팅을 위한 별도 소재를 억지로 만드는 대신 실제 Product Building 경험을 원천 데이터로 사용한다.

---

## 8. 콘텐츠 자동화 방향

추천 방식:
> **자동 생성 → Review Queue → 직접 검토 → 승인 → 예약 발행**

자동화해도 되는 것:
- 소재 추출
- 초안 작성
- 제목 후보
- Threads 버전 생성
- 태그
- 예약 발행
- 성과 데이터 수집

반드시 사람이 검토할 것:
- 사실 여부
- 회사 기밀
- 과장된 성과
- 실제 자신의 생각인지
- 최종 발행

완전 자동 발행보다 **80% 자동화 + 20% 사람 검토**를 지향한다.

---

## 9. KPI

초기 우선순위:

1. 콘텐츠 조회
2. 프로필 방문
3. Prologue& Portfolio 클릭
4. 문의
5. 상담
6. 견적
7. 계약

팔로워 수보다 실제 문의와 계약으로 이어지는 콘텐츠를 더 중요하게 본다.

---

## 10. 고객 문제 데이터베이스

모든 문의에서 기록:
- 업종
- 사용자 유형
- 현재 해결방식
- 가장 힘든 단계
- 발생 빈도
- 사용하는 도구
- 해결 시 기대효과
- 예산
- 실제 계약 여부
- 계약이 안 된 이유

반복적으로 등장하는 문제가 향후 `Prologue&`의 Vertical SaaS 후보가 된다.
