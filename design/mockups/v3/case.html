01Overview

사내 업무 요청을 받아 처리하는 담당자를 위한 요청 관리 도구입니다. 기획·설계·개발 전부를 혼자 맡았습니다.

02Problem

업무 요청이 전화, 메신저, 이메일, 직접 방문으로 흩어져 들어왔습니다. 요청자는 요구를 충분히 정리하지 않은 채 전달하는 경우가 많았고, 받는 사람은 그것을 다시 정리하거나 기억해야 했습니다.

요청이 올 때마다 하던 일이 끊겼고, 진행 상황을 묻는 연락이 다시 요청을 만들었습니다.

03Existing Workflow

같은 좌표계 위에서 기존 흐름(가는 선)이 재설계(굵은 선)로 바뀝니다. 아래로 스크롤하세요.

Before — 4경로가 담당자 한 사람에게 모여 정리·기억에 의존After — 링크 하나 → 구조화된 요청폼 → 심사 Queue → 약속일 → 상태 공유

04Insight

ToDo 관리의 문제가 아니라 요청 Workflow의 문제였습니다.

05Redesign

개인 링크→구조화된 요청폼→하나의 심사 Queue→약속일 확정→상태 자동 공유

요청 단계에서 필수 정보를 채우게 해 되묻는 일을 없앴고, 심사 Queue에서 한 번에 판단합니다. 약속일이 정해지면 요청자에게 상태가 자동으로 공유됩니다.

06Solution

요청폼 · 심사 Queue · 진행 상태 · 약속일 · Dashboard · 요청자 조회 화면.

09What I Learned

도구를 만들기 전에 요청이 들어오는 구조를 바꾸는 것이 먼저였습니다. 처음에 문제를 정리하지 않았다면 더 좋은 ToDo 앱을 하나 더 만들었을 겁니다.
