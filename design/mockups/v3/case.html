01Overview

사내 업무 요청을 받아 처리하는 담당자를 위한 요청 관리 도구입니다. 기획·설계·개발 전부를 혼자 맡았습니다.

02Problem

업무 요청이 전화, 메신저, 이메일, 직접 방문으로 흩어져 들어왔습니다. 요청자는 요구를 충분히 정리하지 않은 채 전달하는 경우가 많았고, 받는 사람은 그것을 다시 정리하거나 기억해야 했습니다.

요청이 올 때마다 하던 일이 끊겼고, 진행 상황을 묻는 연락이 다시 요청을 만들었습니다.

03Existing Workflow

  1. 요청이 들어오는 경로전화 · 메신저 · 이메일 · 직접 방문 — 4갈래
  2. 받는 사람이 하는 일내용을 다시 정리하고, 기억하고, 우선순위를 머릿속에서 매김
  3. 그 다음하던 일이 끊김 → 진행 상황을 묻는 연락이 또 하나의 요청이 됨

04Insight

ToDo 관리의 문제가 아니라 요청 Workflow의 문제였습니다.

05Redesign

  1. 개인 링크요청자는 링크 하나로 들어옵니다
  2. 구조화된 요청폼필수 정보를 채워야 보낼 수 있어 되묻는 일이 없어집니다
  3. 하나의 심사 Queue들어온 요청을 한 화면에서 한 번에 판단합니다
  4. 약속일 확정처리 시점을 정해 요청자에게 알립니다
  5. 상태 자동 공유진행 상황을 요청자가 직접 확인합니다

06Solution

  • 요청폼요청자용. 필수 항목·첨부·희망일
  • 심사 Queue담당자용. 수락·보류·약속일 지정
  • 진행 상태 · 약속일요청 건마다 현재 단계와 예정일
  • Dashboard오늘 접수 · 진행 중 · 평균 처리 · 진행 문의 수
  • 요청자 조회 화면내 요청의 상태를 직접 확인

09What I Learned

도구를 만들기 전에 요청이 들어오는 구조를 바꾸는 것이 먼저였습니다. 처음에 문제를 정리하지 않았다면 더 좋은 ToDo 앱을 하나 더 만들었을 겁니다.
