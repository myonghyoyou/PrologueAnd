심사 대기열: 요청 6건이 한 화면에
01

Overview

회사 안에서 들어오는 업무 요청을 받아 처리하는 담당자를 위한 도구입니다. 기획·설계·개발을 맡았습니다.

02

Problem

업무 요청이 전화, 메신저, 메일, 직접 방문으로 흩어져 들어왔습니다. 요청하는 쪽은 내용을 다 정리하지 않은 채 보내는 일이 많았고, 받는 쪽이 그걸 다시 정리하고 기억해야 했습니다.

요청이 올 때마다 하던 일이 끊겼고, "어떻게 됐어요?"라는 연락이 다시 일을 끊었습니다.

03

Existing Workflow

가는 선이 예전 흐름, 굵은 선이 바꾼 흐름입니다. 내려가면서 보세요.

04

Insight

할 일 관리가 아니라, 요청이 들어오는 길의 문제였습니다.

05

Redesign

요청 링크→요청 양식→심사 대기열 하나→처리 예정일 확정→진행 상황 자동 안내

요청할 때 꼭 필요한 정보를 채우게 해서 되묻는 일을 없앴습니다. 요청은 한 줄로 들어오고, 심사 뒤에 처리 예정일이 정해지며, 진행 상황은 요청한 사람이 직접 봅니다.

06

Solution

요청 양식 · 심사 대기열 · 진행 상태 · 처리 예정일 · 현황판 · 요청자 확인 화면. 아래는 요청하는 사람이 보는 양식입니다.

  • 1무엇이·왜 필요한지는 필수. 비우면 보낼 수 없습니다
  • 2희망일과 영향 범위를 고르면 심사에서 되묻지 않습니다
  • 3보내면 심사 대기열로. 처리 예정일이 정해지면 알림
요청 양식: 요청하는 사람이 필수 항목을 채워 보냄
07

Before & After

Before: 메신저·메일·엑셀·메모에 흩어진 요청
After: 심사 대기열 하나

요청이 들어오는 길 네 개가 하나로. "어떻게 됐어요?" 연락 대신 직접 확인.

08

Impact

4 → 1요청 경로전화 · 메신저 · 이메일 · 방문 → 링크 하나
0회진행 상황 묻는 연락요청한 사람이 직접 확인
1곳심사 대기열예시 수치. 공개 범위를 확인한 뒤 확정
요청 경로4개 → 1개
09

What I Learned

도구를 만들기 전에 요청이 들어오는 길부터 바꿔야 했습니다. 처음에 문제를 정리하지 않았다면 그냥 할 일 앱을 하나 더 만들었을 겁니다.

10

비슷한 문제가 있다면

지금 어떻게 일하고 있는지, 무엇이 가장 불편한지 알려주세요. 이 프로젝트를 붙여서 보내면 같은 맥락에서 바로 답장드리겠습니다.
