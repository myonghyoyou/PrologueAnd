## 1. form.png — 요청 양식 (요청자)

로그인 없이 개인 링크로 들어와 채우는 한 장. 작성이 끝나 보내기 직전 상태다.

**보여주는 것** · 어느 시스템 / 어떤 종류 / 언제까지를 **고르게** 해서, 말로 하면 빠지는 항목이 구조적으로 빠지지 않는다. 화면 이름과 파일 첨부까지 받아 되묻는 왕복을 줄인다. **정리의 부담이 듣는 사람이 아니라 요청하는 순간에 있다.**

**화면 값** — 기능수정(선택) · 제목 `거래처 단가표 양식에 '적용 시작일' 열 추가` · 희망 이번 주 · 화면 `거래처 단가표` · 내용 3줄 · 첨부 `단가표_2026Q3.pdf` `현재양식_캡처.png` · 버튼 `요청하기`

> 첨부는 PDF·PNG 다. 제품이 이미지·PDF·HTML 만 받으므로 글에서 xlsx 로 쓰지 말 것.

## 2. proxy.png — 대리 등록 (담당자)

전화·구두로 온 요청을 담당자가 **그 사람 명의로** 대신 남기는 화면.

**보여주는 것** · 창구를 하나로 모았다는 말이 "요청자만 쓰는 폼"이 아님을 증명한다. 전화로 와도 결국 같은 줄에 선다. 「누구의 요청인가요」 드롭다운 아래는 요청 양식과 같은 구조다.

**화면 값** — 요청자 `최민준 (생산팀)` · 오류(선택) · 제목 `작업지시서 인쇄 여백 수정` · 희망 오늘 · 사유 `출하 서류라 오늘 안에 출력해야 합니다` · 화면 `작업지시서`

## 3. queue.png — 대시보드 + 심사 대기 (담당자)

담당자가 아침에 여는 화면. 상단 지표와 심사 대기가 한 화면에 있다.

**보여주는 것** · 들어온 요청은 전부 여기 모이고, **심사하기 전까지 업무가 되지 않는다.** 카드마다 수락·되묻기·보류·병합이 붙어 있어 되돌릴 수 없는 「수락」 앞에 사람의 판단이 반드시 한 번 선다. 즉답 대신 몰아서 처리하는 자리다.

**화면 값** — 오늘 0 · 새 요청 2 · 이번 주 완료 1 · 약속 임박 2(09/17 까지) · 지연 0 / 심사 대기 2건 · 보류 0 / #846 김서연(53분 전), #845 박도현(2시간 전)

> **쓰지 말 것**: "6건이 표로 보인다", "평균 처리 1.8일", "진행 상황 문의 0" — 이 화면에 없는 값이다. 심사 대기는 표가 아니라 **카드**이고, **아직 심사하지 않은 건만** 담는다.

## 4. tasks.png — 업무 목록 (담당자)

심사를 통과한 요청이 업무로 바뀐 뒤의 모습.

**보여주는 것** · **요청자 칸이 있어** 어느 일이 누구의 부탁에서 나왔는지 한 줄에 보인다. 필터 칩이 「무엇부터 손대야 하나」를 답한다 — 지연 → 오늘 → 기한 순으로 정렬된다.

**화면 값** — 칩: 오늘 0 · 지연 0 · 약속임박 2 · 위임 확인 0 · 이번주 완료 1 · 완료 3 · 배포대기 0 · 전체 3 / 행 3개(검사 결과 엑셀 · 작업지시서 여백 · 검사 이력 기간 필터)

## 5. task.png — 업무 상세 (담당자)

일하는 자리. 메모·처리 내용·요청 맥락이 한 화면에 있다.

**보여주는 것** · **「요청 맥락」 블록**이 원문·요청자·희망일을 업무에 붙여 둔다 — 담당자가 딴 데 찾아보지 않는다. 아래 안내가 규칙을 화면에서 말한다: *"완료하면 요청자 1명의 화면이 바뀝니다. 약속일은 09/19 입니다."*, *"요청이 걸려 있어 이 업무는 삭제도 건너뜀도 되지 않습니다."*

**화면 값** — T-1 `검사 결과를 엑셀로 내보내기` · 메모(열 구성 후보) · 처리 내용 칸 · 요청 맥락 `#844 이지우` · 관련 요청 1건

## 6. status.png — 진행 상황 (요청자)

요청자가 자기 건의 상태를 직접 보는 화면.

**보여주는 것** · 맨 위에 지금 상태와 처리 예정일을 한 문장으로 못 박는다. 약속일은 **담당자가 수락할 때만** 생기므로 추측이 아니라 확정된 약속이다. *"그거 어떻게 됐나요"를 물으러 올 이유를 없앤 화면.*

**화면 값** — `진행 중 · 9/19까지` + `완료되면 바로 알려드립니다.` / 원본 요청(희망 다음 주 · 화면 검사 결과 조회) / 대화: 하늘 담당 9/16 09:10 `엑셀 내보내기 열 구성 확인 중` / 진행: 9/14 14:20 접수 → 9/14 17:20 처리 일정 확정

> 단계 표시가 「접수 → 심사 → 진행 중 → 완료」 **스테퍼가 아니다.** 상태 한 줄 + 진행 이력 목록이다. 요청자 이름 자리에 「나」로 나오는 것은 본인 요청이라서(제품의 실제 동작).

## 7. mylist.png — 내 요청 목록 (요청자)

같은 화면 아래쪽. 내가 넣은 것들이 지금 어디까지 왔는지 한 표로 본다.

**보여주는 것** · **소속 단위로 묶인다** — 「품질팀 요청」이라 동료가 넣은 것도 같이 보인다. 진행 중 / 완료 탭과 정렬(최신순·오래된순·제목 가나다순)이 있다. 목록만 보고도 되물을 일이 없다.

**화면 값** — 「품질팀 요청」 · 진행 중 탭 · 2행(#844 진행 중 `9/19까지`, #839 진행 중)

## 8. news.png — 업데이트 (담당자 · 요청자 공용 창구)

처리한 내역이 쌓이고, 「공개」를 눌러야 요청자에게 나간다.

**보여주는 것** · 무엇이 바뀌었는지가 **자동으로 돌아간다.** 담당자용 글과 요청자용 글을 따로 적어, 내부 용어가 그대로 나가지 않는다. 공개 전에는 초안으로 남아 사람이 다듬을 수 있다.

**화면 값** — 지난 업데이트 2건 / 9/15 18:00 공개(휴가 신청서 승인 흐름 · 발주서 번호 자동 부여 · 정렬 추가) / 9/11 18:00 공개(화면 이름 프리셋 · PDF 첨부) / 각 항목에 `요청자에게 보인 글` · `내림`

## 9. mobile.png — 폰 화면 (390×844)

자리에 없어도 확인하고 처리한다.

**보여주는 것** · 심사 대기 카드가 폰 폭에 맞춰 세로로 서고, 수락·되묻기·보류·병합 버튼이 그대로 살아 있다. 훑는 것이 아니라 **처리까지 된다.**

**화면 값** — 심사 대기 2건 · 보류 0 / #846 김서연, #845 박도현 / 아래로 업무 보드

## 없는 화면

**현황판(board)은 제품에 없다.** 주간 유입·부서별 막대 그래프를 그리는 화면이 존재하지 않으므로 페이지에서 언급하지 말 것. 담당자 라우트는 대시보드 · 업무 · 요청(대리 등록) · 프로젝트 · 피드백 · 업데이트 · 설정 일곱뿐이다.

## 검증

9장 전 화면의 `innerText` 에 `option` · `select` · `placeholder` · `title` · `aria-label` · `alt` 까지 합쳐 뽑아, 운영 DB 의 실제 이름 54건(요청자·오너·프로젝트·화면명)과 실제 요청 제목 75건과 대조했다 — **일치 0건**.

유일하게 걸리는 문자열은 좌상단 로고의 `Por favor, Harry` 로, 제품 이름 자체다.

캡처는 운영 DB 를 전혀 보지 않았다. 빈 Postgres 를 따로 띄워 마이그레이션만 돌리고 위 가상 데이터만 넣었으며, 첨부 업로드도 로컬 임시 서버가 받아 운영 저장소에 파일이 올라가지 않았다.
